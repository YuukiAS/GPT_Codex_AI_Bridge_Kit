The Critic independently read the required AI_Skills governance contracts, Bridge
source/design evidence, and current OpenAI/Git documentation. Three blockers were
reported; the 0.10.0 convergence-release direction itself was accepted.

## BR-ER-F01-GIT-CONFIG-INSPECTION-BYPASS

Requirement: P4 must prove ambient `SSH_ASKPASS` compatibility while
`GIT_ASKPASS`, `core.askPass`, credential helpers and custom Git config remain
fail-closed, with trustworthy preflight before any credential-capable network Git
operation.

Evidence: current `_reject_process_transport_env()` rejects
`GIT_CONFIG_COUNT`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM` and
`GIT_CONFIG_NOSYSTEM`, but not `GIT_CONFIG`. Current safety inspection helpers
use `git config`. Official Git documentation states that `GIT_CONFIG` causes
`git config` without `--file` to read the named file as if `--file` were used,
while the variable does not affect other Git commands.

Risk: preflight could inspect a clean substitute file while a later `git push`
sees the real repository config containing hidden `core.askPass` or an executable
credential helper.

Minimum closure:

- add `GIT_CONFIG` to the custom-config fence;
- perform all security-sensitive config inspection in a stable environment that is
  not redirected by config-source environment variables;
- audit the target Git version's documented config-source / command-scope environment
  inputs;
- add an ER-G4 canary where `GIT_CONFIG` points to a clean substitute while real
  repo config contains malicious `core.askPass` or
  `credential.helper=!<canary>`; fail closed before network/mutation and do not
  execute the canary.

## BR-ER-F02-SANDBOX-FIRST-AUTHORITY-PREFLIGHT

Requirement: P1/P2 must reduce false escalation without skipping genuine authority or
safety gates.

Evidence: Proposal v0.1 said only observed evidence that an effect lies outside the
sandbox/authority may trigger approval. Existing Machine Policy already requires
upfront handling when a frozen Goal declares approval-sensitive private transfer,
paid calls, deployment, resource allocation, Persistent Run launch or similar effects.

Risk: interpreting “observed evidence” as “first attempt and fail” would regress the
existing upfront authorization contract and could defer known authority gates until
mid-execution.

Minimum closure:

- sandbox-first applies to ordinary workspace-contained execution;
- trustworthy static effect analysis, frozen Goal/Plan/contract and existing authority
  contracts may establish a real authority boundary without intentionally causing a
  failed execution;
- preserve existing upfront authorization semantics;
- do not add a new state machine.

## BR-ER-F03-REAL-NORMAL-ENTRY-GATE-BINDING

Requirement: final gates must prove the original combined failure path on the user's
unchanged `codex-cli 0.142.0` environment.

Evidence: ER-G1 bound 0.142.0 only to sandbox-first build. ER-G8 described the
end-to-end consumer path but did not explicitly bind it to 0.142.0 or require a real
normal Codex approval/Auto-review refusal rather than a synthetic refusal fixture.

Risk: evidence could be stitched as “0.142.0 can build” plus “another environment can
recover after refusal” without proving the actual failure combination.

Minimum closure:

- ER-G8 must use the same final Bridge/Machine Policy candidate under a real normal
  Codex entry on `codex-cli 0.142.0`;
- capture a real refusal event, then continue through build/QA, ordinary commit,
  `publish-current-branch`, and remote-SHA verification;
- synthetic refusal/classifier fixtures may supplement but cannot replace the gate;
- if a real refusal cannot be generated safely/stably, keep the capability
  unverified rather than awarding PASS.

## Non-blocking conclusions accepted by Critic

- 0.10.0 as one convergence release remains directionally valid; no real
  safety/owner/recovery reason currently requires a 0.9.4/0.9.5 patch train.
- P1 belongs to Bridge Machine Policy.
- P2 may use existing recovery/authority semantics without a new state machine.
- P3 should be a Bridge-owned no-widening behavior; automatic
  `publish-current-branch -> raw git push` fallback should be forbidden.
- P4's ambient-`SSH_ASKPASS` direction is acceptable if the configuration-inspection
  bypass is closed.
- P5 should compare against formal release identity rather than `main`; active
  executable/import mismatch should fail, non-winning duplicate metadata may warn,
  and `host validate` should not become a network updater.
- The execution Plan must still freeze dirty active editable-source
  warning/failure semantics.

Implementation and execution Goal/Kickoff remain unauthorized until a revised
Proposal closes all three blockers and receives Critic PASS.
