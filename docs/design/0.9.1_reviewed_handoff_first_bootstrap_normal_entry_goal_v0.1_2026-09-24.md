## 1. Positive completion

The task is complete only when one frozen Bridge + AI_Skills candidate pair proves all of the following through normal entry:

1. a brand-new Reviewed task can be first-bootstrapped from one current-user-approved Kickoff using `ai-bridge reviewed-handoff task bootstrap`;
2. `task bootstrap` is not permanently allowlisted and does not inherit the existing permanent `materialize-worktree` allow;
3. branch is derived only as `reviewed/<task_key>`; no caller branch selector exists;
4. exact branch/worktree/base are validated and first REQUEST/CURRENT are created only inside the new reviewed worktree;
5. canonical main is not polluted with temporary task control files;
6. existing `materialize-worktree` remains artifact-bound and low-friction for existing task resume/rematerialization;
7. when local task files/branch/worktree are gone but exact remote reviewed branch contains valid REQUEST/CURRENT, resume reads and validates the remote metadata before checkout and rematerializes successfully;
8. wrong/missing/partial/mismatched task metadata, wrong repo/path/base, symlink/path redirection, occupied/conflicting state and ambiguous partial state fail closed;
9. partial bootstrap rollback removes only clean exact current-invocation objects and never destroys unowned work;
10. AI_Skills `workflow-core` actually routes:
    - task missing -> canonical Bridge `task bootstrap`;
    - task existing locally or on exact reviewed remote -> canonical Bridge `materialize-worktree --mode resume`;
    - missing Bridge capability/version -> early fail before substantive implementation;
    - never raw `git worktree add` or silent alternate path/clone/branch/remap;
11. Bridge releases as 0.9.1 PATCH with current README/CHANGELOG closure;
12. the workflow-core user-visible production routing change receives the required AI_Skills plugin/repository version/changelog closure under current AI_Skills policy;
13. FB-G1 through FB-G5 all PASS on the exact frozen cross-repo candidate pair.

Tests/CI/file existence alone do not satisfy this Goal.

## 2. Frozen architecture

Do not redesign:

- `ai-bridge reviewed-handoff task bootstrap` is the new brand-new-task first-bootstrap entry;
- it is Machine Policy `prompt`, not permanent `allow`;
- `ai-bridge reviewed-handoff materialize-worktree` remains existing artifact-bound permanent `allow`;
- raw `git worktree add` remains prompt/gated and is not the product fallback;
- branch is always `reviewed/<task_key>`;
- first REQUEST/CURRENT live only in the new reviewed worktree;
- one shared internal task initializer owns REQUEST/CURRENT generation;
- resume supports local-complete metadata and remote-only exact reviewed-branch metadata;
- remote metadata is validated before checkout and never copied into canonical main;
- no auth DB/token/receipt store;
- no cross-repo registry/ledger;
- no new watcher/controller/workflow/state machine;
- no destructive/force cleanup.

If implementation requires changing one of these semantics, stop and return Planner/Critic.

### FB-G2 — exact-scope fail closed

Directly test wrong repo, task-derived branch conflict, wrong base ref/commit, wrong path, symlink redirection, occupied/unrelated worktree, unexpected local/remote branch and scope drift.

Verify:

- `task bootstrap` remains prompt;
- raw `git worktree add` remains prompt;
- no alternate branch/path/base is selected.

### FB-G3 — partial-failure recovery

Inject deterministic failures:

- after branch creation;
- after worktree creation;
- during REQUEST creation;
- during CURRENT creation.

Verify only clean exact current-invocation objects roll back. Dirty/ambiguous/unowned state remains with explicit recovery evidence. No force/destructive cleanup.

### FB-G4 — existing lifecycle + remote-only resume

Test both:

1. existing local metadata resume/idempotence regression;
2. remote-only rematerialization:
   - canonical main has no REQUEST/CURRENT for the task;
   - exact remote reviewed branch contains valid REQUEST/CURRENT;
   - helper fetches and reads those files from the remote tree before checkout;
   - validates task/base/path/lineage;
   - rematerializes successfully;
   - wrong/missing remote metadata fails closed.

Also preserve watcher/reviewer publication authority and legal sibling/`/tmp` paths.

### FB-G5 — frozen cross-repo pair / real workflow-core consumer

Load the exact frozen workflow-core candidate through the official normal plugin path with the exact frozen Bridge runtime/Machine Policy.

Real consumer route must demonstrate:

- brand-new task -> workflow-core calls canonical `task bootstrap`;
- existing/remote-only task -> workflow-core calls canonical `materialize-worktree --mode resume`;
- Bridge capability missing/too old -> workflow-core fails early before substantive implementation;
- no raw Git fallback;
- evidence records both candidate commits/versions/runtime identities.

Unit tests/CI/helper-only output do not substitute for this gate.
