## 3. Instruction budget 合同

### 3.1 user-owned

读取actual `project_doc_max_bytes` 与native instruction discovery。

user-owned overflow只报告：

- limit；
- effective total UTF-8 bytes；
- each source bytes；
- cumulative bytes；
- first source where native truncation risk begins。

Bridge不自动删、摘要、重组或改写user rules；用户修正后retry same task。


### 3.2 Bridge-owned mutation

所有root-AGENTS managed mutation先内存模拟，再按同一native discovery计算projected total。

- projected total超过actual `project_doc_max_bytes`或发生native truncation → `BRIDGE_MANAGED_INSTRUCTION_PROJECTED_OVERFLOW`，0 mutation；
- 不对consumer repo额外征收固定20% headroom；
- Bridge约束自己的block贡献：core≤2048、Persistent≤4096、Overleaf≤2048 UTF-8 bytes；
- block超cap属于candidate defect。

当前Bridge root AGENTS为32355 UTF-8 bytes；0.11实现后必须 `root AGENTS <= 24576 bytes`，在默认32768限制下保留至少8192 bytes。详细合同移动到已有正式docs/templates，root只保留稳定不变量+locators。

禁止静默提高用户 `project_doc_max_bytes`。PIE不是Bridge运行依赖。

## 4. Worktree 合同

### 4.1 formal path

新正式task worktree永不自动fallback系统temp。默认repo sibling。

历史已经frozen到 `/tmp` 的旧task保留原locator，不静默迁移；test fixture和partial-clone bounded temp不属于formal task worktree。

### 4.2 G02 T

Bridge内部派生：

`A.parent/.ai-bridge-exchange-<effect-digest>`

same filesystem、stable、unique、empty/nonexistent。

用户不提供T。low-level旧 `--temp-path` 只可作为assertion且必须等于derived T。


### 4.3 activity safety

0.11不声明Linux/procfs或其他平台已经具备可靠automatic quiescence proof。

`/proc`的cwd/root/fd/maps/cmdline、`ps`、`lsof`等可作为“明确发现active process”的diagnostic，但“没有观察到”不能排除watch/inotify、瞬时访问或scan之后新进入A/B的进程，也不能阻止并发访问者。

因此所有production automatic exchange在first move前统一：

`WORKTREE_EXCHANGE_ACTIVITY_UNVERIFIED`

0 mutation。

transaction/journal/rollback继续在disposable、已明确隔离的fixture中测试；fixture PASS不冒充真实worktree quiescence。未来若获得可验证exclusive lease/平台排他原语，必须重新Planner–Critic。

## 7. Unified notification model

唯一transport：

`all producers -> canonical event -> frozen intent -> reader -> Notifier -> Gmail`

三个intent：

`Progress email: ENABLED | DISABLED`  
`Runtime terminal email: ENABLED | DISABLED`  
`Semantic completion email: ENABLED | DISABLED | UNSUPPORTED`

默认全部关闭。

### Progress

start/resume/stage/blocked/stalled/material ETA/cadence；普通count变化不即时通知。

### Runtime terminal

每canonical runtime真实success/fail/cancelled/terminated一次，只写运行事实，不写Goal PASS。

### Semantic completion

只有真实workflow positive authority。

- Lite：UNSUPPORTED
- Reviewed：current Reviewed PASS
- Control：current Critic/Final Critic PASS
- Persistent：无semantic authority

### emitters

- Lite task run
- Reviewed runner
- Control execution owner
- Persistent supervisor

固定runtime owner；Persistent包裹primary时lifecycle owner wins，禁止双发runtime terminal。

Legacy Notifier event types继续兼容映射，不破坏manual send/send-test、milestone、blocked/awaiting-human、dedupe/retry。


## 8. Clear Writing reader contract

### 8.1 production invocation

Runtime在actual selected CODEX_HOME/official app-server中：

1. `plugin/list` / `codex plugin list --json` 验 installed+enabled `writing-style@yuukias-ai-skills` 与actual version；
2. `skills/list` 解析enabled `chinese-prose` 与 `writing-fidelity`，且 `plugin_id` 正确；
3. 每个reader turn以structured `UserInput::Skill {name,path}`选择两skills。

不硬编码plugin cache path，不复制SKILL正文，不使用plugin-replay。

### 8.2 one logical delivery = max one stateless reader turn

Reader只在logical delivery发生时调用。每个event统一使用**fresh ephemeral、tool-free reader thread**：

- neutral Bridge-state cwd；
- 无project AGENTS/Goal/task/source/log/Executor/Progress history；
- `runtime_workspace_roots=[]`；
- execution/external tools关闭；
- 输入只含本次canonical event + language preference +两个structured skills；
- 最多一model turn。

正常result：
- 有Progress display thread时，通过same app-server `thread/inject_items` 注入assistant text；
- email若启用复用同一个result；
- 无Progress thread时email直接使用该result。

Progress thread是durable display/history surface，不执行model reader turn。

### 8.3 fallback

Normal reader失败、plugin/skill不可用、fidelity fail或reader budget耗尽时：

`reader_layer=DEGRADED_FALLBACK`

所有本来应交付的automatic notice都使用确定性短中文fallback，不suppress，不调用第二模型，不推断新事实。

有Progress display thread时fallback也通过 `thread/inject_items` 投影；email复用同一文本。若target runtime不能证明normal/fallback injection可见、持久、reconnect后仍存在，则G14失败且candidate不能freeze。

Reader/Gmail/injection failure不杀primary。

### 8.4 budget / status

Frozen task包含 `Reader render max turns: <bounded integer>`。每logical delivery最多一turn；development canary最多2个fresh ephemeral reader turns。display injection不消耗model turn。

`persistent-run status` / `notifier status` 显示NORMAL_WRITING_STYLE或DEGRADED_FALLBACK、failure reason、last reader turn/time/tokens与last display injection state。

- exact ID identity；
- no execution/external tool surface；
- 0 model reader turns；
- normal/fallback正文通过same-server `thread/inject_items`进入；
- no Executor thread writes；
- no semantic authority。

Model reader只在fresh ephemeral thread执行，所以旧Progress history不进入下一次reader输入。
