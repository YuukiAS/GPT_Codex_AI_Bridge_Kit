## 6. Gate and candidate discipline

按固定顺序推进：

```text
cheap deterministic regression
→ C1_LOW_FRICTION_BOUNDARY
→ C2_CONTEXT_AND_SOURCE_TRUTH
→ C3_MANAGED_INSTRUCTION_WRITE
→ C4_PERSISTENT_LOCAL_LIFECYCLE
→ freeze one final candidate SHA
→ user authorization for C5 live effects
→ C5_ONE_SHOT_CLEAR_WRITING_NOTIFICATION
→ full tests / hosted CI / docs / installed identity
```

C1–C4 不允许用 tests-only PASS 冒充 normal-entry Gate。C5 不允许用历史 055 smoke、旧 G14 canary、fake app-server 或 dry-run 替代当前 final candidate 的真实 one-shot production Gate。

C5 开始后若 production source/template/rules/CLI/version/Gate 标准改变，停止，不自动追加第二次 live model/Gmail；返回 Planner/Critic 重新裁定预算和候选身份。

## 7. Stop conditions

Codex 必须停止并返回 Planner，而不是自行扩项，如果：

- 需要恢复旧 v0.8 runtime architecture；
- 需要新增 daemon/watcher/database/persistent Codex thread/app-server client；
- 需要自动 worktree exchange 或 authorization store；
- 需要改变 C1–C5 产品语义、Gate 或 C4 recovery truth；
- 需要把 Clear Writing 扩成超过一次模型调用；
- 预计核心生产增量超过约 1500 行且原因不是已批准范围内必要错误处理；
- 发现 approved package 与当前 main 出现影响产品语义的冲突；
- 需要新的 provider/data/cost/credential/external side effect。

缺少 C5 live authorization 时，只返回所需 exact user action；此前已完成的实现和 C1–C4 证据继续保留，不回滚、不伪装 C5 已通过。
