## 2. Bridge recovery contract

### Bootstrap mutation ownership

The helper may clean up only objects created by the current invocation and still provably unchanged.

If:

- branch creation succeeds but worktree creation fails;
- worktree creation succeeds but REQUEST/CURRENT initialization fails;

cleanup is allowed only under the Plan's exact identity/cleanliness conditions.

Otherwise preserve partial state and report:

- branch/ref/OID;
- worktree path;
- created task-control paths;
- failing operation;
- dirty/unknown paths.

No force cleanup.

### Remote-only resume

If local REQUEST/CURRENT both absent:

- fetch exact remote reviewed branch;
- read remote REQUEST/CURRENT from its tree before checkout;
- validate identity;
- only then rematerialize.

If one local metadata file exists without the other, fail `LOCAL_TASK_METADATA_PARTIAL`; do not prefer remote as a repair shortcut.

## 3. AI_Skills cutover recovery

The AI implementation cutover is deliberately outside FB-G1.

If raw exact branch/worktree creation succeeds only partially:

- use normal Git inspection;
- delete only exact branch/worktree proven to have been created by this cutover and still clean;
- preserve ambiguous/user-modified state;
- no alternate branch/path;
- no force cleanup.

If AI main moves after cutover:

- fetch latest main for awareness;
- do not silently rebase/recreate the authorized branch;
- before pair freeze, merge/sync only if the approved Kickoff/current repo policy permits an ordinary non-destructive update and it does not change frozen semantics;
- material workflow-core/version conflict returns Planner.

## 4. Candidate pair recovery

A gate failure does not create a successor.

Classify as:

- Bridge implementation defect;
- workflow-core consumer defect;
- Machine Policy/install identity defect;
- candidate loading/stale plugin defect;
- fixture/environment defect;
- approved architecture contradiction.

If repair stays within the frozen architecture, repair the responsible repo, create a new candidate member, re-freeze the pair and rerun affected gates.

Never combine Bridge evidence from pair N with workflow-core evidence from pair N+1.
