## 为什么只修这两处

已通过的产品架构不变：Host HTTPS-only 与真实 no_match、Persistent 真实 producer/ETA/status/durable-first、六席不可退款+终止保留一席、Notifier permit/no-retry、十二项能力、Program Run 排除、历史证据复用和 release 独立授权一律保留。

ER-R0-01 是**验收耦合过度**：此前要求某一真实任务自然产生五次非终止可发邮件事件、第六个被抑制及终止邮件，导致为了凑罕见边界去编排业务阶段。原来真正的两个能力是：（a）真实任务可以报告准确进度、ETA、断线后不重复、外部通知和终态；（b）任何合法事件数超过 cap 时，生产路径会在发生模型/SMTP 效果前阻止第七次。这两个能力都必须证明，但**不要求同一个真实业务任务自然产生罕见的七事件轨迹**。

ER-R0-02 是**真正的执行入口和费用保护缺位**：AI_Skills_Collection main 没有安装 `ai-bridge-text-transform.yml`，旧指定 work branch 不匹配模板的 `main/reviewed/**` push filters。旧 `text_transform.run_text_transform` 在构造 Responses 请求时既不带 max_output_tokens，也未调用 paid_review 的输入 token 计数、调用预算保守预留、失败/歧义回执。即便 1 次试验，也不能靠执行提示词硬限制开销。

这意味着**至少三次远端非强制写入**，而不是旧包文档里的两次：
1. 首次 `work/` task branch push（workflow + 密文 + manifest）；
2. 模型调用前不可退还预算 reservation 写入；
3. 模型结果的加密证据与最终用量 receipt 写回。
