### BC11-ER01：批准提交的唯一定位和单次可发送 Kickoff

明确不做 Program Run、自主发现下一项目任务、第四套 Local Review、独立本地 Reviewer 状态机、控制器、守护进程、权限数据库、仓库全局工作树登记表、按每条误拒绝新建包装器、STAT5060/Lucerna 特化、任意 Git/shell/Python/R 允许规则、危险沙盒开关。不会改变第三方消费者的领域判定；领域自检仍归 AI Skills workflow-core 与相应领域插件。

**后续执行者获批准后可在已确认的本仓库 `main` 现有工作树内**修改任务所必需的 `ai_bridge_kit/`、`templates/host/`、`codex/`、相关 Bridge 安装模板、`tests/`、`docs/`、`README.md`、`CHANGELOG.md`、`pyproject.toml`、`ai_bridge_kit/__init__.py`、必要 CI 测试配置。只允许常规本地构建/测试、可丢弃隔离 Git/仓库/Host 假体、精确任务文件的普通提交、已存在同名 origin/main 的非强制安全发布及其远端 SHA 核验；不允许自动改用户真实机器或其他仓库。实测数据不包含真实私人论文/凭据。任何 GitHub 临时远端或用户机器、SMTP 收件人、真实账号/凭据、Machine Policy 安装/替换、live release 引用推进均另按下文授权关卡。

## 4. 同一实现阶段的顺序和退出条件

### S0 — 基线、权限和回归库冻结（只读取证）

在实际 Kickoff 后确定唯一现有 main 工作树/对应 origin、source HEAD、必要工作树/平台身份；核 Bridge `release=0.10.0`、真实安装版、Git/Codex 可执行版本及有效 `CODEX_HOME`，检查当时最新 AGENTS、源码、机器规则与测试。已存在脏文件不自动 reset/stash。列出现有普通入口与安全负例：Reviewed/bootstrap/resume/publish-first、publisher GitHub HTTPS askpass/config、Persistent Run、Notifier、Host、Lite、Control 通用角色 prompt。以当前冻结 Design PASS 为权威，发现源码大幅变化时报告冲突回 Planner/Critic；不更新其他仓库。

定义开发回归输入和 Gate 的真实运行顺序、批准环境、评审者读取权限；所有便宜确定性负例先运行。阶段成功只证明基线可诊断，**没有**新产品能力。

### S1 — 有效指令预算 + 预检公共内核（先做最早失败）

改动点主要为 `cli.py`、`host.py` 或一个小型共享 `readiness.py`（仅为复用纯函数而建，非控制器），必要模板/规则和对应测试。遵从**被测实际 Codex 版本**的配置优先级、项目根标记、从根到 cwd 的 AGENTS.override.md/AGENTS.md/fallback 名称、按字节跨层累积、用户级指令与项目级预算分离、UTF-8/BOM/CRLF、重复受管标记、实际截断尾段。确认超限严格非零，未知有效配置或启动覆盖则 UNVERIFIED（会阻断受检入口但不伪称所有原生入口被保护）。

Bridge 根现有 AGENTS.md 大于默认 32,768 字节，不能只加验证然后让正常维护任务永远失败：按真实生效配置验证当前 Bridge 根，必要时将**详细仓库治理材料**搬到恰当的有明确加载入口的引用文件，精简自动发现的 AGENTS，但要在正常受检任务由实际读取路线消费所有强制规范，不删改受保护安全含义，不把“移到未自动读的文件”误报为已加载；变更前后语义比对并跑 G07/G08。其他 consumer 不自动改写其 AGENTS。

公共 preflight 只读取目标任务/工作树、当前 Host/runtime/release/有效项目规则/实际必需文件，输出准确成功或具体阻断类型；不自动修机器、下载插件或改变 CODEX_HOME。先在确定性 fixture 验证配置覆盖、真实指令发现和不相关可选模板不会误挡任务。

### S2 — Mandatory control-file 取得、来源校验与启动器接通

优先实现固定仓库+origin+固定提交+必读路径的隔离 Git 对象读取；用 `GIT_OBJECT_DIRECTORY` 将新对象写入工作区受限临时目录，用原对象库作为 `GIT_ALTERNATE_OBJECT_DIRECTORIES` 只读候补；检查真实 git object 类型、路径/提交身份，验证原 .git 对象库、refs、FETCH_HEAD、index、config 无变化；配置/transport/凭据/过滤器未验证则拒绝，绝不允许 generic `git show`。主生产形状仅已配置并证明安全的 GitHub HTTPS origin；此前 Linux Git 2.47.3 `file://` 探针只作机制证据。按来源大小和可输入限制拒绝无法完整读入的控制文本；用固定提交+字节 SHA 明确区分真实已读与仅看到路径。

将公共 preflight 注入 Reviewed `watcher_once` 与 `run_codex_event`；必须**把前置成功与 record_event_start 的写入顺序纠正**：先完成所有只读+必要受限读取，重读/比对受检查点及本次 task identity（避免同步后版本变化），才记录真实启动尝试，然后立即进入子执行进程。子执行前复核不得依赖冗余重复外部获取，需用已绑定的不可伪造的同进程检查结果复用，若状态变化则 fail closed。失败不得算执行 attempt，也不得更改 CURRENT/审查预算；失败影响等待/运行状态时只记可恢复的诊断，不能把状态改为终态。

Lite `task run` 只针对已有、可唯一定位的 Lite task，获取全部必需控制文本并作为严格标明“这是仓库资料，不是用户授权”的上下文交给 Codex；固定合法执行目录及可执行身份，未预检成功不得启动子进程。Control 只在已有显式 task identity 的具体受管转换中检查；`agent-flow prompt <role>` 原通用入口保持原样和兼容测试。

**正面结果**：G03/G04/G07/G09 通过本阶段获得真正的被调用路径，而不是只多一个验证命令。

### S3 — 任务工作树连续性与严格安全 Git

不动不同分支并行的现有长期工作树；任务预检绑定被选 worktree/common-dir/branch/HEAD，旧候选仅作只读证据。仅实现 Proposal v0.2 的**两个普通关联工作树**、同一文件系统、用户已明确双端最终路径的双脏交换；优先三步原生 `git worktree move`，如需要只设计一个原子授权效果的受限入口。逐步核验 Git admin 目录、路径/符号链接、文件/索引/分支身份、主工作树、锁/子模块/活跃进程条件；操作前保存仅本次恢复用途的证据；S1/S2/S3 各中断点按来源与内容核验后只作允许的反向 move，不可证明就停止不擅动。未获得用户对“无关脏工作转移到 B”的确切授权时不得启动交换；本 Kickoff 只授权实现与**可丢弃双端模拟**，不授权真实用户工作树迁移。

增加 `ai-bridge host sync-current-branch`：已检出、已追踪的**当前同名非 main** 现有 origin 分支，完全 clean、ancestor/fast-forward-only、无 merge/rebase/autostash/额外 refspec、post OID 一致，配置/传输安全沿用 0.10.0 publisher 审查；错 repo/分支/upstream、dirty、diverged、危险 credential/helper 均无副作用失败。原生 Git/gh 只读前缀按**所有可接受尾部形状**证明安全才放行；危险 Git show/log/diff 的外部扩展及任意远端始终走正常审核。不重复生成已有 Reviewed publisher。

### S4 — 授权连续性、拒绝恢复与有限进度送达

保留真实当前用户聊天授权与 repo Goal 线索的信任等级；同一任务同一个已授权 effect 在实现阶段不重复 `HUMAN_ONLY`，但 CLI 自带的 `--authorized` 或仓库自称 authorized 绝不授新权。已有 Host/sandbox 拒绝按 optional / sandbox-capable-wrong-route / bounded-entry-broken / genuine boundary 一次分类；只允许同范围最小合法恢复，受限入口失败不得回退原始宽 Git。保留 build/render/QA/commit 等各自证据与 checkpoint，不因 publication 未完成就否认它们。

修复持久进度现有发送残余：在已有任务进程、调度器或已授权调用方主动提供的真实进度证据到来时，复用 `persistent_run.report_progress_file`、Notifier v2 的 `operational_progress`，且真实决定权只能是已有 Controller/Watcher。发现进度变化不能绕过最短间隔频繁发信；重要阶段/真正 stall/blocked 等可有边界的即时报告。真实来源不足则 ETA=UNKNOWN，送达失败不冒称发送，不为“周期性”新增独立守护进程/轮询器/新传输层。无已授权 SMTP 收件人和配置，不发送真实邮件、不回显凭据，G14 留待单独真实关卡。

### S5 — 0.11.0 候选完整准备、冻结唯一提交、同源正式验收（BC11-ER02）

## 7. 分阶段失败与无损恢复合同

- **预检失败**：明确缺失的 Host/规则预算/工作树/来源，子 Codex 未启动、执行次数和 CURRENT 不变化；一次合法外部更新 + fresh 会话 + 同 Goal、同 checkpoint 恢复。
- **双工作树交换中断**：只有受支持 A/B/T 拓扑；保存前置精确双端 dirty/index/HEAD/路径/Git admin 证据后才进入三步；按实际目录及管理身份识别 S1/S2/S3，合法时官方逆向 move；混入第三方变化立即停止，保护中间态与所有文件，不运行 prune/reset/clean/force。
- **部分克隆缺对象/恶意 helper**：隔离目录失败不触碰原 Git 对象目录；强制控制源仍未读时禁止依赖操作，不把普通 sandbox 失败当作要求 escalated 的理由；只返回准确未解决来源。
- **安全非主分支同步失败**：前置安全检查失败不改变 ref/工作树；真实并发导致中途失败时记录前后 HEAD/remote，禁止改用 rebase/reset/raw pull；仅同分支授权恢复。
- **一次误拒绝**：按照已存在四分类仅允许安全等价路线；bounded helper 失败不能自动回退 raw broad Git；保留已成功 build/test/render/commit，失败的 publication/status 只影响其对应效果。
- **真实宿主 Gate/通知不可达**：明确 UNVERIFIED/ENVIRONMENT_COVERAGE_GAP；不借未见样本、测试字串、假邮箱/模拟凭据冒充外部效果 PASS；保留最终候选/证据，等待确切 user-only 授权或 Critic 裁定，不制造后续自动任务。
- **安全/架构不成立**：只有改变范围、权限、关键恢复、Gate 或正式发行承诺才返回 Planner–Critic 方案修改；普通局部实现缺陷由 Executor 在原 Goal 内修复并重做受影响回归。
