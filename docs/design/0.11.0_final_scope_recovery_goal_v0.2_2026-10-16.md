## 1. 正面完成标准

最终唯一 C' 必须同时实现并证明：

1. Persistent Run 由真实 run/process lifetime owner 持有 ticker，默认约 60 分钟主动向**原 Codex task thread**报告；无任务理由不得低于 15 分钟。
2. start/resume、重要 stage、stalled/blocked/failed/runtime completion、material ETA 可提前。
3. observation 与 last logical delivery 分离；fraction/count小变化不刷屏，频繁 observation 不饿死 cadence。
4. exact thread 仅：
   - 已存在 thread 内真实 `CODEX_THREAD_ID` + shared app-server复核；
   - Bridge child 官方 `thread.started.thread_id`。
   不按标题/cwd/时间/repo文件猜。
5. shared app-server只是必要条件；每次thread write必须另外具备**原子idle-only保证**：官方与同一write request绑定的fail-if-active/expected-idle，或所有真实writers共同参与的可证明排他边界。status-read + later request、Bridge-local lock、单一connection都不够。
6. P0-A在任何write前先证明上述atomic guard；two-client race必须让delivery fail/defer且不进入active context。当前0.160.1无已证明expected-idle接口时不得假定可写。
7. A合法失败后才可能P0-B；P0-B除atomic guard外，还必须在同exact thread/turn的模型请求**之前**机械关闭全部execution/external tool surface。prompt/output_schema/read-only sandbox/事后tool-call检查都不够；当前0.160.1若无supported same-thread机制则B直接UNSUPPORTED、零model turn。
8. A/B任何必要机械前提不成立或route失败 -> `UNSUPPORTED_WITH_EVIDENCE` 停止，不用email/manual latest冒充。
9. `send_message_to_user_async` 仅研究参考：UnderDevelopment/default-off/DirectModelOnly，不作为成熟 Bridge route。
10. machine SMTP profile一处配置多项目消费，project profile只兼容覆盖；secret路径/权限/symlink fail closed。
11. `Progress email` 与 `Semantic completion email` 独立、缺省DISABLED；**automatic/derived send**必须重读frozen intent；`notifier once/run`同属automatic。
12. 当前用户亲自执行 `ai-bridge notifier send <brief>` / `send-test` 是该次one-shot effect授权，不要求历史Goal补intent；manual live entry必须机械拒绝Bridge/Codex automation冒充人工路径。
13. automatic semantic completion不能只信brief的 `decision_authority` 字符串；必须绑定并通过现有 Reviewed PASS artifact 或 Control Final Critic PASS artifact 的 exact task/current candidate/terminal decision validator。无适用artifact的Lite不得automatic发Goal complete。
14. Host Policy只allow真实证明安全的native reads；不安全保持gated；不造read wrapper。
15. `plugin-replay` KEEP_NARROW，不扩成通用Reviewer。
16. G01–G05、G07–G13不降级；G06/G14按Plan恢复。
17. 所有生产修改后冻结新C'；final gates/CI/installed Bridge/Machine Policy/Codex identity只绑定C'。

## 4. P0 route contract

获批准Kickoff后，先做**无write的atomic-guard capability inspection**。只有官方atomic fail-if-active/expected-idle或所有实际writers共享的可证明排他边界成立，才允许P0-A；普通read-idle + later write不算。two-client race必须证明另一client抢先启动turn时progress不会进入active context。

只有A合法失败、atomic guard仍成立，而且actual runtime另有same-thread/exact-turn **pre-model mechanical no-tool confinement**时才允许一个P0-B；prompt/schema/read-only/事后检测不能替代。当前0.160.1若没有该supported机制，B直接UNSUPPORTED、不启动模型。

P0只是开发机制选择，不是final Gate。最终C'仍须重新证明atomic race safety、UI可见、reconnect、非user message、active defer与canonical snapshot一致；B路线还要重验机械tool isolation和restore。

## 5. Reporter contract

- report可频繁观察；
- last observed / last delivered独立；
- user cadence基于last delivered；
- fraction/count小变化只观察；
- immediate事件/material ETA按Plan；
- foreground report-loop由actual run owner持有；
- owner/terminal/signal后确定性cleanup；
- owner无法绑定则该topology不claim proactive reporting；
- reporter不能cancel/restart/扩资源/改Goal。

## 6. Notification contract

Frozen Goal/task：

`Progress email: ENABLED | DISABLED`  
`Semantic completion email: ENABLED | DISABLED`

缺失=DISABLED。Automatic progress、`notifier once/run`和任何automatic semantic completion都必须重读该source；progress JSON self-asserted auth无效。

当前用户亲自在交互终端执行 `notifier send` / `send-test` 保持one-shot兼容，不需要历史task intent；automatic workflow不得调用manual path绕过。Manual live path必须区分并拒绝Bridge/Codex自动上下文。

Automatic semantic completion还必须验证existing workflow的真实decision artifact：Reviewed current PASS + matching REVIEW/implementation + FINAL_REPORT，或Control current Final Critic PASS + request_nonce/review_target/bundle绑定。仅写 `decision_authority` 字符串无效；Lite无artifact时automatic no-send。

SMTP优先级：machine default < project override < process env。Machine/private路径必须安全，不回显secret。
