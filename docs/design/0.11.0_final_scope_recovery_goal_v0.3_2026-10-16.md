## 1. 正面完成标准

最终唯一 C' 必须同时实现并证明：

1. Persistent Run 由真实 run/process lifetime owner 持有 ticker；默认约 60 分钟主动汇报，无任务特定理由不得低于 15 分钟；start/resume、重要 stage、stalled/blocked/failed/runtime completion、material ETA 可提前。
2. observation 与 last logical delivery 分离；fraction/count 小变化不刷屏，频繁 observation 不饿死 cadence。
3. 每个 Persistent Run normal entry **自动创建或复用一个 dedicated Progress thread**，与 exact repo/task/Goal/run 唯一绑定；用户无需自己创建 thread，也无需手工 status/query。
4. Progress thread 必须是 **non-ephemeral persistent thread**；同一 run reconnect/resume 后复用 exact thread id，历史仍可查看且不重复创建。
5. Progress thread 只显示 progress，不执行任务、不做 Planner/Reviewer/Executor、不拥有 semantic completion authority，也完全不写原 Executor/task thread。
6. Progress thread 的安全配置优先复用官方 temporary/structured thread 的**能力关闭模式**，但不能复用其 ephemeral 生命周期。必须机械关闭 shell/unified exec/web/plugins/apps/MCP/environment/runtime workspace/dynamic tools/multi-agent/external connector 等 execution/external surfaces；若 actual runtime 无法机械证明这一点，则实现 blocker。
7. 每个 user-facing logical delivery 只允许一个 bounded render turn。Bridge 先确定 canonical snapshot；model 只呈现既定 stage/status/count/fraction/ETA/UNKNOWN，不重新估计、不改变数值、不规划、不评审。
8. Progress thread 自动设置可发现的确定性名称，但 name 不作 authority；machine-local binding 以 exact thread id 为唯一恢复身份。
9. reporter/run 生命周期结束后，允许 Progress thread 历史继续存在，但不得再产生新消息。
10. runtime completion 只显示 runtime state，不等于 Goal semantic completion。
11. 旧原 Executor thread 注入路线明确退出：`P0_A=UNSUPPORTED_ATOMIC_IDLE_GUARD` 只作为未采用技术路线记录，不再是 release blocker；不运行 `thread/inject_items`、atomic idle guard、same-thread turn/start、two-client race 或 same-thread tool-confinement。
12. machine SMTP profile 一处配置多项目消费，project profile 只兼容覆盖；secret 路径/权限/symlink fail closed。
13. `Progress email` 与 `Semantic completion email` 独立、缺省 DISABLED；automatic progress、`notifier once/run` 和 automatic semantic completion必须重读 frozen intent。
14. 当前用户亲自在交互终端执行 `ai-bridge notifier send <brief>` / `send-test` 保持 one-shot compatibility；automatic workflow不能借 manual path绕过。
15. automatic semantic completion必须绑定既有 Reviewed PASS artifact 或 Control Final Critic PASS artifact；伪造 `decision_authority` 字符串无效；Lite无适用artifact时automatic no-send。
16. Host Policy只allow真实证明安全的native reads；不安全保持gated；不造read wrapper。
17. `plugin-replay` KEEP_NARROW，不扩成通用Reviewer。
18. G01–G13原定义不降级；G14-A/B/D/E保持，G14-C按dedicated Progress thread验证。
19. 所有生产修改后冻结新C'；final gates/CI/installed Bridge/Machine Policy/Codex identity只绑定C'。

## 4. Progress thread route contract

旧原-thread P0-A/P0-B 不再运行。`P0_A=UNSUPPORTED_ATOMIC_IDLE_GUARD` 只说明原 active task thread 外部安全注入路线没有被采用。

获批准 Kickoff 后，Phase 0 只做 dedicated Progress thread canary：

- 自动创建一个 non-ephemeral persistent Progress thread；
- 使用官方 temporary/structured helper 的 deny-config pattern，但明确 `ephemeral=false`；
- 自动命名并保存 exact progress_thread_id；
- 在任何 model render turn 前机械证明 execution/external tool surface被关闭；
- 最多两个 bounded render turns；
- UI可见；
- canonical snapshot fidelity；
- exact ID reconnect/history；
- 原 Executor/task thread完全不变；
- canary结束后不再产生新消息。

若 actual runtime 无法机械证明 dedicated Progress thread 无执行/外部能力，则 `PROGRESS_THREAD_ISOLATION=UNVERIFIED_BLOCKER` 并停止；**不回退原 Executor thread注入**。

开发 canary不能替代 final C' G14-C。

## 5. Reporter contract

- report可频繁观察；
- dedicated Progress thread是正式 user-facing thread target；email/manual latest不能替代；
- last observed / last delivered独立；
- user cadence基于last delivered；
- fraction/count小变化只观察；
- immediate事件/material ETA按Plan；
- foreground report-loop由actual run owner持有；
- owner/terminal/signal后确定性cleanup；最后 runtime snapshot 后 reporter退出，Progress thread历史保留但不再新增消息；
- owner无法绑定则该topology不claim proactive reporting；
- reporter不能cancel/restart/扩资源/改Goal。

## 6. Notification contract

Frozen Goal/task：

`Progress email: ENABLED | DISABLED`  
`Semantic completion email: ENABLED | DISABLED`

缺失=DISABLED。Automatic progress、`notifier once/run`和任何automatic semantic completion都必须重读该source；progress JSON self-asserted auth无效。

当前用户亲自在交互终端执行 `notifier send` / `send-test` 保持one-shot兼容，不需要历史task intent；automatic workflow不得调用manual path绕过。Manual live path必须区分并拒绝Bridge/Codex自动上下文。

Automatic semantic completion还必须验证existing workflow的真实decision artifact：Reviewed current PASS + matching REVIEW/implementation + FINAL_REPORT，或Control current Final Critic PASS + request_nonce/review_target/bundle绑定。仅写 `decision_authority` 字符串无效；Lite无artifact时automatic no-send。

SMTP优先级：machine default < project override < process env。Machine/private路径必须安全，不回显secret。
