## Finding

### BR-ER-ER-F05-STAGE-B-CANDIDATE-ENTRY-BINDING

The reviewed Plan/Goal already required Stage B to:

1. materialize the exact final candidate;
2. create an isolated candidate venv/install;
3. temporarily install candidate Machine Policy;
4. start a fresh normal Codex process;
5. run ER-G1/ER-G3/ER-G8 under the same candidate identity.

The execution-ready package did not yet freeze the canonical fresh-Codex launch or
candidate PATH identity, and its future Stage B authorization text did not positively
authorize isolated candidate activation plus fresh normal Codex launch.

Current Bridge source also resolves the trusted Bridge executable using
`resolve_ai_bridge_executable() -> shutil.which("ai-bridge")`. Therefore invoking
`host install` from an absolute candidate executable alone does not prove that
Machine Policy will pin that candidate if an older production `ai-bridge` remains
earlier in PATH.
