## 2. Remaining RL-B2 defect

Plan v0.4 correctly required the standard full-heads origin fetch refspec, but two Git configuration facts remained:

### 2.1 Deprecated skip synonym

Git still treats:

```text
remote.<name>.skipDefaultUpdate
```

as a deprecated synonym for:

```text
remote.<name>.skipFetchAll
```

Therefore checking only `remote.origin.skipFetchAll` is insufficient.

The trusted safe class must reject origin if either skip setting can exclude it from `git fetch --all`.

### 2.2 Additional configured remotes

`git fetch --all --prune` processes all participating configured remotes.

Another remote can have its own fetch refspec and destination namespace. A custom refspec could write/prune refs that overlap or interfere with the local namespace used as origin truth.

For 0.9.1, supporting arbitrary multi-remote/refspec combinations is unnecessary.

The smallest mechanically safe rule is:

> the trusted first-bootstrap safe class supports exactly one configured fetch remote: `origin`.

No generalized refspec conflict solver is introduced.

---

## 3. External Git reality rechecked

Official Git documentation was rechecked for this revision:

- `git fetch --all` fetches all remotes except remotes excluded by the skip-fetch setting;
- `remote.<name>.skipDefaultUpdate` is a deprecated synonym of `remote.<name>.skipFetchAll`;
- when no command-line refspec is supplied, `remote.<name>.fetch` controls what refs are fetched and where remote-tracking refs are written;
- negative refspecs can exclude matching refs;
- pruning follows the configured fetch mapping.

Adopted consequence:

> authoritative remote-branch absence for the trusted bootstrap is claimed only for an ordinary single-origin clone-style configuration.

Anything else exits the low-friction safe class and remains on ordinary/manual handling.

## 4. Final strict canonical fetch safe class

Before the workflow relies on:

```text
git fetch --all --prune
```

and before the standing-allow bootstrap may mutate topology, require all conditions below.

### 4.1 Exactly one configured remote

Require the configured Git remote set to be exactly:

```text
origin
```

No second remote is accepted by the trusted path.

Examples that fail closed:

```text
origin + upstream
origin + mirror
origin + backup
any other additional configured remote
```

The helper does not inspect whether a second remote is “probably harmless”. 0.9.1 deliberately avoids cross-remote destination/refspec analysis.

Failure semantics:

```text
NONCANONICAL_REMOTE_CONFIGURATION_REQUIRES_ORDINARY_APPROVAL
```

Exact error string is implementation detail; fail-closed semantics are frozen.

### 4.2 origin must participate in fetch-all

Require both keys independently to be absent or false:

```text
remote.origin.skipFetchAll
remote.origin.skipDefaultUpdate
```

Because `skipDefaultUpdate` is the deprecated synonym, the trusted profile does not rely on Git's last-occurrence precedence to reconcile conflicting values.

Strict safe-class rule:

- absent = acceptable;
- explicit false = acceptable;
- any true value = reject;
- conflicting/invalid values whose safe meaning cannot be proven = reject.

Do not rewrite either key.

### 4.3 exact canonical fetch refspec

Require exactly one effective `remote.origin.fetch` value:

```text
+refs/heads/*:refs/remotes/origin/*
```

Reject:

- main-only mapping;
- multiple fetch refspecs;
- negative refspecs;
- custom destination namespace;
- mirror-style mapping;
- any alternate/mixed mapping.

Do not attempt semantic equivalence normalization in 0.9.1.

### 4.4 no configuration mutation

The trusted path never:

- edits remote config;
- deletes a second remote;
- changes skip flags;
- rewrites refspecs;
- renames origin;
- converts an exotic repo into the canonical profile.

It simply exits the trusted low-friction bootstrap path.

## 5. Authoritative sync sequence

Only after the strict canonical profile passes:

### Step 1 — configured-remote sync

Run the existing already-allowlisted:

```text
git fetch --all --prune
```

Because the repo has exactly one remote and both skip flags are safe, this fetch necessarily includes origin.

Because origin has the exact full-heads mapping, every remote branch head is represented under:

```text
refs/remotes/origin/*
```

and prune applies to that same complete heads mapping.

### Step 2 — capture post-sync base

Read:

```text
refs/remotes/origin/main
```

and record its exact OID.

This OID is the only accepted `--expected-base-commit` for trusted bootstrap.

### Step 3 — inspect reviewed task branch

Inspect:

```text
refs/remotes/origin/reviewed/<task_key>
```

If present:

```text
REMOTE_TASK_BRANCH_ALREADY_EXISTS
```

and first bootstrap does not run.

If absent, remote task-branch absence is authoritative for the supported safe class.

### Step 4 — trusted bootstrap re-check

Immediately before mutation, the bootstrap helper re-checks:

- configured remote set = exactly `origin`;
- both origin skip flags safe;
- exact one canonical fetch refspec;
- local `origin/main` equals `expected-base-commit`;
- local `origin/reviewed/<task_key>` is absent;
- all previously accepted RL-B1 and repo-local path/branch fences.

Then and only then may local branch/worktree creation begin.

## 6. Bootstrap remains network-free

The standing-allow `task bootstrap` helper performs zero network operations.

Forbidden inside bootstrap:

- `git fetch`;
- `git ls-remote`;
- remote/provider API;
- push;
- remote branch creation;
- remote mutation.

The network boundary remains:

```text
existing allowlisted git fetch --all --prune
-> local authoritative refs
-> network-free bootstrap
```

This is unchanged from v0.4.

---

## 7. Minimal implementation shape

No new command or wrapper is required.

The existing Reviewed Handoff source gets one narrow canonical-remote-profile validator that answers only:

```text
1. Are configured remotes exactly ["origin"]?
2. Are skipFetchAll and skipDefaultUpdate absent/false?
3. Is remote.origin.fetch exactly one canonical full-heads mapping?
```

The bootstrap calls this validator immediately before trusting local remote-tracking refs and before first mutation.

The workflow may perform the same check before `git fetch --all --prune` to fail earlier, but helper-side re-check is mandatory.

No generic Git config auditor/refspec parser framework is introduced.

## 11. Red Team for the final RL-B2 closure

Attack:

1. `skipDefaultUpdate=true` while `skipFetchAll` is absent/false;
2. both skip keys exist with conflicting values;
3. a second remote has a refspec writing into `refs/remotes/origin/*`;
4. a second remote exists but appears unused;
5. canonical origin plus second mirror remote;
6. workflow checks remote count but helper forgets to re-check;
7. origin config changes between sync and bootstrap;
8. local `origin/main` changes after expected base is captured;
9. bootstrap performs hidden network after standing allow;
10. noncanonical repo is silently normalized instead of rejected;
11. real AI_Skills gate skips recording its actual remote configuration.

The intended result for every noncanonical configuration is fail closed, not broader support.
