## 2. 正面完成标准

在同一个获批准的生产版本 `0.11.0` 候选内，Bridge 正常任务入口应：稳定执行在绑定 worktree/branch；允许两个不同长期分支的工作树并行；在严格允许的两个普通关联双脏树的授权交换情况下无损且可恢复；在受限 GitHub HTTPS partial clone 中从被保护对象库外取得已冻结控制文件并于实质执行前读取；当前现有非 main 分支只做同名 origin 严格快进；危险邻近 Git 路线仍被保护；有效 Host/project instructions/版本身份不符时在受管进程启动前阻断；一次合法外部 Host 更新 + fresh session 可以保持同 Goal/checkpoint；既有授权无重复 HUMAN_ONLY，真正新权依旧请求；一次真实子 Codex 拒绝不扩权限和不丢已完成效果；Persistent Run 的既有真实进度能在已有授权进程/Notifier 下真正周期性、低打扰送达。旧 0.9.x/0.10.0 能力不能回归。

**只有 G01–G14 在同一最终候选上按 Plan 达到真实标准，完成对应 CI、独立预终审及必要用户外部效果授权，并按正式分发 owner 机制真正发布/读回 release，才能对整个 0.11.0 声称已发布并完成。** 单纯源码开发和本地 CI 只可称对应阶段完成；真实平台或通知 Gate 不可达记 UNVERIFIED，不编造 PASS。

## 3. 必须执行且不得扩大的一致路线

1. **先审环境**：读取 `AGENTS.md`、全部获审 Plan/Goal、Bridge 当前 main/release、0.9.0–0.10.0 回归/真实规则与目前实际 Git/Codex/Host；核源/分支/工作树/dirty 状态。若不匹配，停止非法副作用，不自行更换路径、分支或仓库。
2. **真实启动关卡优先**：把 Codex 当前有效项目指令发现/按字节累计检查并入 `ai-bridge validate --strict`；使用真实有效 CODEX_HOME/配置/根标记、AGENTS.override.md/AGENTS.md/后备名称、UTF-8/CRLF/BOM；confirmed truncate 非零、UNKNOWN 不得 PASS。Bridge 根现有 39,688 字节超默认 32,768 限时，应无损整理当前根规则与受管内容实际读取，而非删减必要合同或只使字数测试变绿。
3. **Mandatory 控制文件**：只读固定 repo/origin/commit/文件，partial clone 缺 blob 时仅通过临时隔离对象目录（`GIT_OBJECT_DIRECTORY` 写入、原对象库 `GIT_ALTERNATE_OBJECT_DIRECTORIES` 只读候补）真实取得、验证来源提交和完整内容。只允许经证明安全的 GitHub HTTPS 身份；不写原 .git/refs/FETCH_HEAD/index/config、不放宽 generic `git show`，不使用非批准 provider/凭据；读失败不得启动依赖效果。
4. **真实入口消费**：Reviewed `watcher_once` 和 `run_codex_event` 都能前检，先于 `record_event_start` 完整取得必需资料，失败子进程=0、执行尝试数/审查状态不变；Lite 新增唯一薄 `ai-bridge task run --target <worktree> --task-key <key>` 并在成功前检后只启动原生 `codex exec -C`；Control 只对已有任务身份的受管交接做检查，**保留无 task key 的 `agent-flow prompt <role>` 兼容**。直接原生 Codex 不属于被强制预检入口。
5. **工作树**：两个不同分支长期 worktree 正常并存，不主动收拢/移动。唯一支持的双脏真实交换是**两个普通关联工作树，同一 common-dir/文件系统、路径 A/B/T 可信、没有锁/子模块/不明链接/并发进程，且用户同时明确许可无关分支与目标分支的两个最终位置**；按三次原生 `git worktree move`，每步校验、保留独立 index/HEAD/dirty 内容与中断后反向恢复。主工作树或未获双端授权直接 `UNSUPPORTED_WITH_EVIDENCE`，不强行尝试，也不 globally allow git worktree。
6. **安全 Git**：现有、已追踪、已选择的非 main 分支只允许严格同名 origin fast-forward；前置安全配置/远端/clean/head ancestry，后验 OID，失败不 autostash/rebase/reset/force。只对真正可证明任意尾随参数安全的只读命令下发细粒度 execpolicy，保留 ext-diff/textconv/helper 与危险变更的审批路径。Reviewed bootstrap/first publish 和已有 publisher 不重造。
7. **权限和恢复**：用户当前消息中的具体授权优于 repo 自称，当前用户已给出的 exact same effect 不重复 HUMAN_ONLY；平台的真实边界依旧有效。拒绝按 0.10.0 的四类归因，只走已批准的同范围恢复，bounded helper 失败绝不 fallback raw broad Git。任何失败保留 build/render/QA/commit/checkpoint；Host stale 可在**新获授权后**外部一次安全更新，fresh Codex 同 Goal 恢复，不假称热重载。
8. **进度**：不重造 Persistent Run 归一化/本机历史/Notifier；只修已有执行者/调度器持有真实进度事件的有限送达路径。已授权既有 Notifier 真送达、阶段和慢/停滞分明、频率适中、ETA 无依据 UNKNOWN；不加 watcher/daemon/自动干预/新权限。
9. **回归、候选与发行**：源/Host 模板/安装/codex-cli/CODEX_HOME 全部唯一绑定，按 Plan G01–G14、已有安全负例、CI 及 pre-final Critic 检验；对不可复现的真正子 Codex refusal 或真实通知只报 UNVERIFIED，不拼不同候选结果。0.11.0 package/changelog/README/TODO 必须与**实际**正式发行一致；独立获得用户明确批准确切 `refs/heads/release` 旧→新非强制快进后才由 AI Skills Maintainer 管理正式发布。

- 初始拟定的 live 最终验证上限：同一冻结候选合并执行的**最多 8 个**新鲜 Codex 会话，30 分钟以内单次诊断时间；不得基于旧候选采样无限跑到成功。若真实覆盖不足，先报明确缺口并重新请求获授权的预算/范围，不能默默追加。外部付费 API 的预算为零。
- Program Run、第四套 Local Review、授权库/全局工作树表、新监视器/控制器/守护进程、通用 shell/Python/R/Git allow、`danger-full-access`、`approval_policy=never`、仓库特定修复、强制所有原生 Codex 会话安装 Bridge，全部排除。

## 5. 阶段性结果与停损

执行过程在本仓库合法结果路径持久保留关键证据：开始时 repo/worktree/source identity；S0 现状；S1–S4 真实实现与测试；S5 同一候选逐 Gate 的 PASS/FAIL/UNVERIFIED、Host/运行身份、外部效果；Pre-final Critic 的真实路径或 chat-only 标志；发行后才提交正式 release 关闭记录。凡敏感日志、凭据、私人数据不得提交公共仓库；需要时只在本机已有合规 private 路径做脱敏导出。

每个 Gate 明确真实普通入口和失败轨迹。不能用「测试绿、源码存在、被拒模拟、读到了控制路径、写了规则、进度本地 JSON、旧正式版本 evidence」代替真实能力。Goal 未全部通过时给可操作的阶段事实、最小未闭合效果、恢复方式；**绝不**因为局部成功声称整体完成。需改变获批设计、Gate、权限或发布路线时停止相应扩大实施并交回 Planner–Critic。最终同版执行 Plan 与 Kickoff 是本 Goal 的不可偏离绑定合同。
