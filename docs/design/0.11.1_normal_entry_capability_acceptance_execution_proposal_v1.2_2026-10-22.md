## R2-01 唯一剩余阻塞：候选 Host 程序不匹配现有机器可信路径

正式 0.11.1 的 Host 规则用 `host_executable.paths` 绑定已安装 `ai-bridge` 的真实绝对路径；它不会因为候选程序同名就信任位于 `candidate-venv/bin/ai-bridge` 的 0.11.2。上一版执行包错误地要求候选路径同时满足正式机器的预装 `allow`，导致本来合法的候选验收被无意义阻断。

**唯一修法不是改白名单，而是保持三种证据各司其职。** 第一，候选通过已冻结绝对 CLI、原有 `workspace-write` 与 `on-request / auto_review` 正常审批执行安全包装器，直接证明真正的 HTTPS 快进以及危险 Git 在效果前被拒绝；候选 `no_match` 只意味着没有预自动放行，并不构成自动授权或产品失败。第二，当前已装 0.11.1 的机器规则由其可信旧 CLI 与 Codex 原生规则检查只读核对，保留合法 Git read/add/commit 等低打扰操作与危险原始 Git 的审批；静态规则检查不冒充运行时已加载状态，实际批准/拒绝仍由当前 Codex 会话观察。第三，对未来候选路径的规则匹配仅允许隔离模拟，结论只能是 `WOULD_MATCH_AFTER_INSTALL`，不能冒充当前 `allow` 或在本任务更新机器策略。

真实候选 Host 正向验证使用 v1.2 已冻结的 AI_Skills 消费者同名工作分支：在现有授权的三次写回完成后，通过候选 CLI 进行一次正常 HTTPS 快进并比较 OID，不增加远端写或账号权限。需要平台审批时仅针对这个精确作用按现有机制办理；不得使用软链接/PATH 替身、旧可信 CLI 代执行、通用 shell/Python 放行或修改 `CODEX_HOME` 绕过。详细命令、失败分支与证据口径保存在同版 Plan/Kickoff。

本轮没有重开已通过的 ETA、R1 终态、Persistent、六席预算、Text Transform 或十二项产品架构。R2 审查结论由用户转交，未提供独立仓库 review 文件，不冒充已归档的原文；上述只是实施前待独立 Critic 复核的最终窄修订。
