## User Capability

Bridge Kit now provides a production B0 wrapper:

```bash
ai-bridge candidate-plugin-replay \
  --target <repo> \
  --plugin <plugin-name> \
  --candidate-commit <sha> \
  --task <explicit-task-file> \
  --input <explicit-input-file>
```

The command is a sibling of `ai-bridge plugin-replay`. It does not change
`plugin-replay` semantics.

The candidate plugin is resolved only from the target repository commit's
committed `.agents/plugins/marketplace.json`. The wrapper requires exactly one
matching local-source entry, stages the candidate plugin from the commit tree,
creates a Bridge-owned temporary marketplace name, installs only the temporary
candidate plugin identity, verifies installed path and tree digest, runs a fresh
`codex exec --ignore-user-config` child with the existing replay sandbox
contract, requires installed-path runtime consumption evidence, and then removes
only the Bridge-owned candidate plugin and staging directory.

## Safety Boundaries

- No B1 implementation or fallback was added.
- No persistent `codex plugin marketplace add/remove` path was added.
- No `--plugin-path` or arbitrary candidate directory escape hatch was added.
- No alternate `CODEX_HOME`, auth/config copying, production plugin overwrite,
  production same-name disable loop, global config restore, release tag, branch,
  PR, package version bump, or 051-specific logic was added.
- Root probe-only `.agents/plugins/marketplace.json` was removed from the Bridge
  repository, so the Phase 0 `visualize` fixture is no longer exposed as the
  repository's canonical marketplace.

## Host Policy

Host Policy templates now include a narrow allow for:

```text
ai-bridge candidate-plugin-replay
```

`ai-bridge host validate` checks that this wrapper is allowed while raw mutation
commands remain non-allowed:

```text
codex exec
codex plugin add
codex plugin remove
codex plugin marketplace add
codex plugin marketplace remove
```
