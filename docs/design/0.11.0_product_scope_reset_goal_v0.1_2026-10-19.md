## 3. Required implementation results

### C1 — Host Policy

必须保留 Execution Plan §4 的 safe command shapes 与 `host sync-current-branch`，并保持危险 remote/refspec/helper、rebase/autostash、force/delete、branch/worktree mutation、reset/clean/restore/stash、credential/release 等邻近操作 gated。

不得增加 generic Git wrapper/controller。

### C2 — exact execution/source truth

实现唯一顺序：

```text
exact repo/worktree/branch/expected_commit
→ HEAD exact match
→ mandatory path validation
→ local exact blob with GIT_NO_LAZY_FETCH=1
→ only-if-object-missing isolated fallback
→ blob/text/digest binding
→ spawn
```

必须满足：

- unrelated dirty files 不构成全局 blocker；
- mandatory path 与 expected commit 不一致时 fail closed；
- source authority 始终是 exact commit blob；
- isolated fallback 只接受 exact repo + 40-hex commit + repo-relative path；
- fallback 只把临时 objects 写 Bridge state；
- 原 `FETCH_HEAD`、index、config、refs 与 object store 保持不变；
- 任一 mandatory source 失败时 model/Executor child count = 0；
- Lite、Reviewed、Control 只在各自真正 Executor spawn boundary 前消费该 preflight；
- 不恢复通用 readiness controller。

### C3 — managed writer projection

只保留 writer-facing helper。真实消费者固定为 Lite/core、Persistent、Overleaf。

每个 writer 必须在该次调用任何项目文件 mutation 前完成 projected-byte 与 block-cap 检查。overflow/config-unverified 时零 mutation；不得自动删改用户 instructions、摘要用户文本或提高 `project_doc_max_bytes`。

### C4 — local Persistent lifecycle

exact launch identity、full-64-hex session name、binding path 与 supervisor `--launch-id` 必须按 Execution Plan §7 机械绑定；不得为此新增 tmux user-option registry。

必须严格实现：

```text
no binding + no session -> new start
compatible binding + exact active session -> existing
nonterminal binding + missing session -> UNKNOWN/UNAVAILABLE, no relaunch
session exists + missing/mismatched binding -> conflict, no takeover
terminal binding -> read-only terminal facts, same run key no rerun
partial start -> no guessing/relaunch
supervisor loss -> no restart/no false terminal
exit_code -> only from observed child.wait()
```

Persistent start/status 不得依赖 app-server、Progress thread、Notifier 或 Clear Writing。

### C5 — one-shot Clear Writing

automatic owner 已经决定发送之后才调用 adapter。manual `notifier send` / `send-test` 保持 0.10 行为。

每个 logical delivery：

- 最多一个 fresh `codex exec --ephemeral`；
- `--json --sandbox read-only`；
- 不 `resume`；
- 不第二模型修复；
- model run 前唯一确认当前 installed/enabled `writing-style@yuukias-ai-skills`；
- runtime 必须可证明实际消费 `writing-fidelity` 与 `chinese-prose`；
- stdout JSONL normal success 必须 exactly one `turn.started`；
- protected 数字、状态、`UNKNOWN`、路径、版本、identity、结论强度通过机械检查；
- plugin/skill/model/JSONL/turn/fidelity 任一失败立即 fallback；
- fallback 仍尝试 existing Notifier transport；
- expression/transport failure 不改变业务状态、不杀 primary；
- 不创建 app-server client、persistent reader/session、Progress thread 或跨 workflow event bus。

## 9. Stop / return rules

普通实现 bug、同范围 deterministic regression failure 由 Codex 在本 Goal 内修复。

出现以下任一情况必须停止并回 Planner–Critic：

- 需要恢复任何已删除旧架构；
- 需要改变 C1–C5 scope/Gate；
- 需要增加 daemon/watcher/database/persistent thread/app-server client；
- 需要扩大权限、外部 provider/data/cost；
- 需要改变 C5 one-shot budget；
- 需要改变 C4 stale/partial recovery semantics；
- 生产增量复杂度明显越界且无已批准解释。

未获 C5 external authorization 时，在真实 C5 前停止并报告精确所需用户动作；不得用 mock/dry-run 冒充 Gate PASS。

正式 `release` 永远不属于本 Goal 的自动执行范围。
