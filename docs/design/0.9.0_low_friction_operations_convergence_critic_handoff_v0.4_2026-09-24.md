==================================================

v0.4 changes only the trusted publisher transport claim.

Trusted low-friction supported positive path:

https://github.com/<owner>/<repo>.git

with existing system/global credential manager / gh credential helper.

Not a trusted-positive path:

- git@github.com:<owner>/<repo>.git
- ssh://git@github.com/<owner>/<repo>.git
- other SSH/scp-style remote
- custom remote helper/transport

trusted helper must fail closed before remote/network publication and return to
ordinary raw git push approval.

Bridge must not:
- create/upload SSH key;
- start/manage ssh-agent;
- modify ~/.ssh/config;
- modify known_hosts;
- switch HTTPS remote to SSH;
- add a second SSH wrapper.

Please decide whether this is a legitimate product-scope narrowing aligned to real user need,
rather than an improper weakening of a required capability.
