# v0.3.0 Generic Notifier Design Note

Status: design note for the v0.3.0 notifier work.

CARE's `controller_notifications/` implementation is the real-use reference,
but the Bridge Kit generic core must stay small. Project complexity belongs in a
Project Profile.

## Keep In Generic Core

- `notification_brief.json` as the explicit terminal handoff from controller or
  goal logic to notifier.
- Terminal-only notifications. The notifier sends only when a brief says the
  task is terminal.
- One-shot sending as the default path.
- Send-once / deduplication through a small event key and content digest.
- Failed-send retry by not marking failed sends as sent.
- Persistent local send state under `.ai-bridge/state/`.
- Plain text plus HTML email.
- Gmail SMTP over port 587 with STARTTLS.
- Dry-run support.
- Real `send-test` support.
- First polling startup baselines existing terminal briefs instead of backfilling
  old notifications.
- Email failure records local status and returns a nonzero result for one-shot
  sends without making polling mode permanently exit.

## Keep Out Of Generic Core

- CARE `route_A`, `route_B`, and `route_C`.
- MyoPS, Cine, nnU-Net, Slurm, GPU, or training-specific semantics.
- Slurm mandatory fields.
- CARE-specific result paths.
- `CARE_*` environment variable names.
- CARE-specific tmux session/window names.
- CARE worktree assumptions.
- CARE Codex runtime-home candidates.
- Route watchboard behavior.
- CARE goal SQLite as the only event source.
- Immutable notification transactions, multi-receipt hash coupling, moving Git
  SHAs, and large historical manifests.

## Default Runtime Shape

The default path for a new repository is:

```text
Goal / Controller terminal state
-> write results/<task_key>/notification_brief.json
-> ai-bridge notifier send results/<task_key>/notification_brief.json
-> SMTP email
-> local success/failure state
-> stop
```

No tmux, daemon, systemd unit, background service, process supervisor, or
polling loop is required for the default notifier semantics.

`ai-bridge notifier once` and `ai-bridge notifier run` exist for compatibility
and operational preference only. They are not prerequisites for
`NOTIFIER_READY`.

## Digest Boundary

The notifier digest exists only to suppress duplicate email sends for the same
brief content. It must not become:

- scientific provenance;
- Agent-Flow review identity;
- release identity;
- immutable transaction identity;
- CI gate identity;
- Planner evidence identity.

No hash ledger is introduced for v0.3.0.
