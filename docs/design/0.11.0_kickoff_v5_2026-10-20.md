## 实施边界

必须保留 Lite/Review/Control 既有 authority。Persistent 只拥有 runtime facts。Notifier 只拥有 transport。Clear Writing 只拥有表达。

机器级 Notifier 一台 OS 用户配置一次；repo-local notifier.env 只可作显式 migration input；production normal entry 的 SMTP user/password/FROM/default TO/subject 等 transport config 只能来自 ~/.ai-bridge/private/notifier.env，AI_BRIDGE_NOTIFY_* 进程环境不得覆盖。recipient_override 只允许来自已冻结任务合同。

实现完成后必须停止在新的 exact production candidate：提交受影响回归、完整 tests、hosted CI、diff boundary 和冻结的 Persistent normal-entry canary/budget，然后交同一 Critic做 PROCEED_TO_FINAL_EVALUATION / REVISE。无论机器上已有何种 Gmail/model 凭据，本次 Codex implementation 阶段都不得运行新的 live final Gate。

如果实现要求改变 v5 产品语义，或出现 Proposal/Plan 明确禁止的新控制层，停止并返回 Planner/Critic，不要边写代码边重新设计。
