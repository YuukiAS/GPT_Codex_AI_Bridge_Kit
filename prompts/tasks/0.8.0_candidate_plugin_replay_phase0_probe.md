## 最终目标

只回答一个问题：

> 当前真实 Codex runtime 上，Bridge Kit 0.8.0 的 candidate plugin replay 应选择 A、B0、B1，还是当前仍 NOT READY？

Phase 0 结束时必须得到且只得到以下之一：

```text

SELECTED_MODE=B0

SELECTED_MODE=NOT_READY
```

不要在本任务中实现 `candidate-plugin-replay` production wrapper、Host Policy capability、CLI command、lock/journal runtime、release/version bump 或其他 0.8.0 production code。

## 权限与安全边界

本次允许的 raw Codex plugin/exec 操作仅限于 Plan v0.2 冻结的 A/B0/B1 **一次性 research probe**。

如果当前 Codex / Host Policy 要求确认，正常走确认。不要为了无人值守而提前放宽 raw：

```text
codex plugin add
codex plugin remove
codex plugin marketplace add
codex plugin marketplace remove
codex exec
```

不得：

- 切换或复制另一个 `CODEX_HOME`；
- 复制 `auth.json` 或其他 credentials；
- persistent disable/overwrite/remove 用户现有 production plugin；
- snapshot/restore 整个 Codex 环境或 `config.toml`；
- 为 B0 发明“挑选并复制 model/provider/proxy 用户配置”的系统；
- 新增 B2/B3；
- 新增 schema、ledger、state machine、adapter framework、lock framework 或 chaos framework；
- 修改现有 `plugin-replay` 语义；
- 把 AI_Skills 051 的 heavy-route receipt/写作语义塞进 Bridge；
- 修改或发布任何 unrelated user work。

如果 probe 需要越过这些边界，停止并记录 `SELECTED_MODE=NOT_READY` 或返回 Critic，而不是自行扩大 scope。

## Probe 顺序：严格 A → B0 → B1

### A — repo/cwd marketplace only

目标：验证未安装 candidate 是否仅凭 repo/cwd 下的 committed marketplace 就能被 fresh Codex runtime 实际加载。

要求：

- 只做一次短 probe；不要为 A 写 infrastructure；
- 必须有真实 runtime consumption + candidate identity proof，不能只看发现列表；
- 若 A 意外成功：立即停止，不继续 B0/B1，不写 production code，输出 `SELECTED_MODE=A_RETURN_TO_CRITIC`。
- 若 A 失败或无法证明，进入 B0。

### B0 — process-local marketplace + plugin add + `--ignore-user-config`

这是首选路径。

使用一个无害、generic、具备**独特可观察行为**的本地测试 plugin；需要能够与一个同名 production/test identity 形成 collision 场景，但不得破坏真实 production plugin。

候选来源必须来自一个真实 Git commit 的 committed `.agents/plugins/marketplace.json`。按 `--plugin` 找唯一 local source；不得从 dirty working tree 猜路径，不得使用 `--plugin-path`。

B0 要求：

1. 从 committed manifest stage candidate marketplace/plugin；
2. 只通过 Bridge 生成的 `-c` marketplace config 让 `codex plugin add` 找到 candidate；**不得 persistent `marketplace add`**；
3. 安装 candidate 后记录：candidate commit、manifest entry/source path、staged digest、installed plugin ID/path/digest；
4. 用 `codex plugin list --json` + B0 的 Bridge config 做 effective-plugin preflight；注意这只是 preflight，不等同于 exec runtime proof；
5. candidate install 完成后、child 启动前，hash 当前 `$CODEX_HOME/config.toml`；
6. fresh child 必须使用同一 `CODEX_HOME` authentication，并用：
   - `codex exec --ignore-user-config`
   - Bridge-owned candidate marketplace/plugin `-c` overrides
   - natural harmless task
7. child 必须出现 candidate plugin 的独特无害行为，作为真实 runtime consumption proof；
8. child 退出后、任何 cleanup 之前再次 hash `$CODEX_HOME/config.toml`，必须与 step 5 相同；若不同，B0 失败并 fail closed，不 restore；
9. remove candidate plugin 与 staging；
10. 验证原有同名 production/test identity 未被修改。

如果 B0 PASS：记录 `SELECTED_MODE=B0`，立即停止，不运行 B1，不写 production code。

如果 B0 真失败：记录明确 failure evidence；不要修 B0、不要复制用户 config，进入 B1。

### B1 — persistent temporary marketplace + plugin add + same-name process-local selection

仅在 B0 真实失败后运行。

要求：

1. 使用 unique temporary candidate marketplace；
2. persistent marketplace add 后安装 candidate；
3. candidate 与已有同名 production/test identity 并存；
4. 用同一组 process-local overrides：其他同名 identity disabled，candidate enabled；
5. `codex plugin list --json` 只作为 effective preflight；
6. fresh child 使用完全相同的 selection config 跑 natural harmless task，并必须表现 candidate 独特行为；
7. child 前 / child 后 cleanup 前的 `config.toml` hash 必须一致；
8. cleanup 只删除本次 candidate plugin、candidate marketplace、staging；
9. 验证已有 production/test identity 未变。

如果 B1 PASS：记录 `SELECTED_MODE=B1`，停止。

如果 B1 失败：记录 `SELECTED_MODE=NOT_READY`，停止。不要继续寻找其他替代方案。

## Crash/journal 说明

本轮不实现 production OS lock / `active.json` runtime。

只有当 A/B0/B1 已经选出生产模式后，才对最终选中的模式做 Plan v0.2 中定义的一次 Smoke C；如果在不写 production code 的前提下无法合理完成 Smoke C，则在 Phase 0 报告中明确把它标记为“selected mode 后续 implementation gate”，不要为了完成本 Goal 先实现 lock/journal subsystem。

不要用这一点扩大本轮 scope。

- 不越过一次性 research probe 权限边界；
