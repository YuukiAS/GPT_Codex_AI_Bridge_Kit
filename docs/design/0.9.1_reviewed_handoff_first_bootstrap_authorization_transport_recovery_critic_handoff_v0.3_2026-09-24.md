2. RL-B1-UNSANDBOXED-EXECUTION-FENCE
==================================================

v0.3 adds a deliberately bounded fence for only executable mechanisms reachable
by the permanently allowed bootstrap command sequence.

Before the FIRST topology mutation, the helper must fail closed for:

- executable reference-transaction hook;
- executable post-checkout hook;
- executable post-index-change hook;
- effective core.hooksPath variants of those hooks;
- external filter.*.smudge;
- external filter.*.process;
- external command-valued core.fsmonitor IF the retained implementation/rollback
  path can invoke it.

Boolean built-in core.fsmonitor is not rejected merely for being true.

The Plan permits an equivalent simpler implementation:
if an executable mechanism is reachable only because of a removable helper
command (for example rollback git status), Executor may remove that command path
instead of adding another general scanner.

The preflight itself must not use a Git command that triggers the executable path
it is inspecting.

Review whether this closes the unsandboxed command-execution escape without
turning Bridge into a generic Git security scanner.
