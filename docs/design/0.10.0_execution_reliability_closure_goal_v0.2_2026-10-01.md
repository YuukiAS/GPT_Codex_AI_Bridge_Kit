## 7. P4 exact publisher security contract

### 7.1 Rejected process config/transport inputs

Before security-sensitive Git inspection, reject:

```text
GIT_CONFIG
GIT_CONFIG_GLOBAL
GIT_CONFIG_SYSTEM
GIT_CONFIG_NOSYSTEM
GIT_CONFIG_COUNT
GIT_CONFIG_KEY_*
GIT_CONFIG_VALUE_*
GIT_CONFIG_PARAMETERS
GIT_SSH
GIT_SSH_COMMAND
GIT_ASKPASS
GIT_PUSH_OPTION*
```

Do not replace this with an unbounded `GIT_*` sweep.

### 7.2 Stable inspection view

Every security-sensitive Git config/remote/hook read must use one stable environment
that removes the caller-controlled config/transport inputs above.

The stable view must see the repository's actual normal config stack.

At minimum route the current equivalents of these reads through that view:

- config value lookup;
- config key existence;
- scoped/origin config list;
- effective fetch/push URL resolution;
- config-backed hooks path.

Do not inspect under one config view and perform network work under another.

### 7.3 Repository fences

Continue to fail closed for:

- effective `core.askPass`;
- local/worktree/command executable `credential.helper`;
- effective custom SSH transport;
- active pre-push hook;
- mirror/followTags/submodule recursion/push options/signed push;
- wrong/multiple/effectively rewritten URLs;
- wrong repo/branch/upstream;
- SSH/scp/custom transport.

Normal accepted system/global GitHub HTTPS credential-manager behavior must remain
usable.

### 7.4 Ambient SSH_ASKPASS

Do not reject inherited `SSH_ASKPASS` solely because it exists.

Before the first authentication-capable remote/network Git command:

- construct the sanitized network environment;
- remove `SSH_ASKPASS`, `GIT_ASKPASS`, the config-source/command-scope inputs and
  rejected transport variables;
- set `GIT_TERMINAL_PROMPT=0`;
- use the same sanitized environment for remote read and final push.

Any required authentication-capable network operation before this point is a design
violation and returns Planner/Critic.

### 7.5 Required canaries

`GIT_CONFIG` bypass:

```text
GIT_CONFIG -> clean substitute
real repo config -> malicious core.askPass or credential.helper=!canary
=> fail before network/mutation
=> canary execution count = 0
```

`GIT_CONFIG_PARAMETERS` bypass:

```text
GIT_CONFIG_PARAMETERS -> executable credential.helper command config
=> fail before network/mutation
=> canary execution count = 0
=> variable absent from stable inspection and sanitized remote/push
```

No raw push fallback.
