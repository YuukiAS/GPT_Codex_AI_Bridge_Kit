## BR-ER-F01 closure to verify

v0.2 已明确：

- 把 GIT_CONFIG 纳入 config-source fence；
- 同时保留 GIT_CONFIG_GLOBAL / GIT_CONFIG_SYSTEM /
  GIT_CONFIG_NOSYSTEM / GIT_CONFIG_COUNT / KEY / VALUE；
- security-sensitive git config inspection 必须使用显式 stable environment；
- stable environment 必须让 preflight 看真实 normal config stack，
  不能被 caller 的 GIT_CONFIG 指向干净替代文件；

- ER-G4 增加：
  GIT_CONFIG=clean substitute，
  real repo config 存在 malicious core.askPass 或 credential.helper=!canary，
  必须在 network/mutation 前 fail closed，canary execution count=0。

请独立检查 Git 官方当前文档，确认 v0.2 是否还漏掉等价的正式 config-source /
command-scope environment input，或者 stable inspection 设计是否仍有 config-view
split。

## BR-ER-F02 closure to verify

v0.2 已删除“必须先 observed sandbox failure 才能确认 authority boundary”的语义。

现在冻结：

- sandbox-first 只管 ordinary workspace-contained execution；
- current user authorization、frozen Goal/Plan/contract、
  existing authority contract、可信 static effect analysis
  都可在执行前证明真实 authority boundary；
- private transfer、paid/external API、deployment、migration、
  scheduler/resource allocation、Persistent Run 等现有 upfront authorization
  语义继续有效；
- 不要求故意执行失败；
- 不新增状态机。

请检查这是否足以同时防止：

1. repo-local build 被错误 escalation；
2. 已知高影响 effect 被拖到执行中途才处理。
