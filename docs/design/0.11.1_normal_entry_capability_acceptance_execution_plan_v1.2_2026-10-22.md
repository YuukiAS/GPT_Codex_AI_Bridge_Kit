## 4. ETA 与通知预算的不同证据
ETA 不需要真实业务自然耗满十分钟。同一最终候选的生产 update_run_progress、normalize/observe_binding_progress、estimate_progress_eta、status/history 用真实格式但隔离受控时钟数据 (0,2/12),(300,5/12),(600,8/12)，same stage/total/run_id，预计余4项400秒；检查第三点由 UNKNOWN 到估计、经验区间与阶段/总数变化、平台、源坏/停更、重复/未来时间的合理 UNKNOWN/失败。受控时钟只能作用在测试边界，不修改生产 ETA 算法，不在真实邮件中输出这些合成时间，报告不可写成真实任务经历十分钟。独立真实正向任务必须从最终 candidate 正式 start 到真实 producer/Supervisor/status/history、installed writing-style、真实 machine Gmail、terminal；不睡眠、模拟进度或重复最终任务凑门槛。
预算极端测试由同一 candidate 在本地隔离状态从正式 persistent-run start 进入生产 Supervisor→binding→Notifier permit，按受控合法不同事件证明 5+1、不同第七个正常非终止事件在 helper 前 model0/SMTP0、terminal 专席不可抢占、失败/DELIVERY_UNKNOWN/崩溃/恢复/retry/wrong permit 不退款或重发；只可在外部发送边界记录调用，不能替换生产 permit/预算算法，更不能把故障模拟当成真正 Gmail 正例。
