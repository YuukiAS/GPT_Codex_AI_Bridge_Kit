# Bridge Kit 0.7.3 — Unattended Host Diagnostics Hardening

Status: implementation contract for the next patch release. This document does not itself change the installed Host Policy.

## Why this is a 0.7.3 patch

Bridge Kit `0.7.2` fixes the reproduced Slurm false-positive by preauthorizing a narrow set of direct read-only scheduler inspections. New production evidence shows that unattended Codex work can still be terminated when automatic approval review rejects other low-risk host operations needed for diagnostics, including:

- host-level current-user process inventory such as `ps -u <user> -o pid,ppid,stat,etime,cmd` when the sandbox process namespace is insufficient;
- safe Git synchronization such as `git fetch --all --prune`.

This is not evidence that all shell commands should be trusted. It is evidence that unattended reliability now depends on a second, still-bounded Host Policy layer for common read-only host inspection and synchronization. This remains a safety/default-behavior correction to the existing Host Policy and therefore belongs in `0.7.3` rather than a new workflow release.

## Product outcome

On a trusted Codex host with Bridge Kit Host Policy installed:

1. previously reproduced harmless host-inspection operations should not be delegated to automatic approval review when Bridge Kit can express a bounded safe route;
2. commands that mutate process state, scheduler state, repository topology, user files, or external systems must remain gated;
3. unattended/overnight work should prefer the narrowest already-authorized command shape instead of escalating to a broader equivalent without need;
4. Bridge Kit must not disable Auto-review, switch to danger-full-access, or add broad `bash`/`sh`/Python trust merely to avoid interruptions;
5. release claims require real execpolicy validation plus at least one production smoke test on an affected remote Codex identity.

A unit-test PASS is not enough if the affected unattended workflow still dies on a normal read-only diagnostic.

## Reality: what 0.7.2 does and does not solve

`0.7.2` directly allows:

- `squeue`, `sinfo`, `sacct`, `sstat`, `sprio`;
- `scontrol show ...` and `scontrol ping`.

It does **not** directly allow raw host `ps`, nor `git fetch --all --prune`. Deploying `0.7.2` is still required for the Slurm fix, but these newer failures are independent and will remain until separately addressed.

The current Host Policy already allows `git fetch origin main`. Therefore, when a task only needs to refresh `origin/main`, the preferred behavior is to use that narrower preauthorized command rather than `git fetch --all --prune`.

## Design principle: do not solve read-only friction with a giant allowlist

The right model remains:

- exact command-shape allow rules for operations whose semantics are sufficiently bounded;
- bounded wrappers when safety depends on runtime facts such as current UID or dynamic scope;
- approval for genuinely broader or mutating operations.

Do not blanket-allow `ps`, `git fetch`, `bash`, `sh`, `zsh`, `env`, `xargs`, Python, `sudo`, `kill`, `pkill`, or arbitrary scripts.

## Git synchronization policy

### Narrow command preference

If the task only needs current `origin/main`, Codex should use:

```text
git fetch origin main
```

which is already preauthorized.

Do not broaden a simple source-of-truth refresh into `git fetch --all --prune` merely because the broader command is familiar.

### Exact `--all --prune` compatibility rule

The reproduced command itself is still a common read/synchronization operation over already-configured remotes and does not mutate the worktree or user branches. `0.7.3` may preauthorize the **exact** command shape:

```starlark
prefix_rule(
    pattern = ["git", "fetch", "--all", "--prune"],
    decision = "allow",
    justification = "Allows bounded synchronization of already-configured remotes and pruning of stale remote-tracking refs without changing the worktree or local branch topology.",
)
```

If the implementation also wants to support the semantically equivalent option order `git fetch --prune --all`, add that exact shape separately after real execpolicy validation.

Do **not** replace this with `pattern = ["git", "fetch"]`. Generic fetch accepts arbitrary repositories, URLs and refspecs, including forms capable of updating unexpected local refs.

Required negative checks should include representative arbitrary-refspec and arbitrary-URL fetch commands remaining outside the direct allowlist.

## Host process inspection: use a bounded wrapper, not raw `ps`

The reproduced process check needs host visibility because sandbox-local `ps` may only see the isolated process namespace. A raw executable-level `ps` allow rule would be too broad: process listings can cross user boundaries or expose unnecessary command/environment details depending on options.

`0.7.3` should therefore add one small Bridge-owned read-only host inspection entry point, preferably under the existing host namespace, for example:

```text
ai-bridge host processes
```

The exact CLI name may follow current parser conventions, but its contract must remain narrow.

### Wrapper contract

The wrapper must:

- inspect processes owned by the current effective UID only;
- require no caller-supplied username or UID;
- use a fixed safe field set sufficient for stale-background-task diagnosis, such as PID, PPID, state, elapsed time, terminal, executable/command and command line;
- never include environment variables;
- never invoke `sudo`;
- never signal, stop, renice, kill, reparent, attach to, or otherwise mutate processes;
- never inspect another user's processes by caller request;
- never accept arbitrary `ps` flags or shell fragments;
- produce deterministic plain-text or JSON output suitable for Codex diagnostics;
- be executable through the trusted `ai-bridge` host executable pin, not via a repo-local fake executable.

If command-line arguments may contain obvious credentials, implement conservative redaction for common secret-bearing forms where practical, but do not silently drop process identity needed for diagnosis. The wrapper must never request or print process environments.

### Execpolicy rule

Only the bounded wrapper should be directly allowed. Raw host `ps` remains on the approval path.

## Unattended-operation behavior contract

Automatic approval denial may terminate the current Codex operation before repository-level workflow prose can recover. Therefore the primary defense is prevention, not pretending a terminated tool call can always be caught after the fact.

Update Host AGENTS guidance so unattended/overnight work follows this order:

1. prefer an already-preauthorized narrow command when it answers the question;
2. prefer a Bridge-owned bounded wrapper when host visibility or dynamic scope is required;
3. do not escalate to a broader command merely because the narrow command is inconvenient;
4. if the only remaining path genuinely requires user approval, do not substitute a dangerous workaround or silently weaken the task.

Do not claim that AGENTS prose alone makes an approval denial recoverable. If the product runtime terminates a turn on denial, the Host Policy must prevent predictable low-risk denials up front.

## Auto-review remains enabled

Do not disable `approvals_reviewer = "auto_review"` as the solution to this incident. The intended architecture is still:

- sandbox for hard execution boundaries;
- Host Policy rules for known low-risk operations;
- automatic/human approval for higher-risk or unclassified operations.

Turning off automatic review would merely replace these false denials with unattended approval stalls and would not solve overnight reliability.

## Required acceptance matrix

### Must resolve to direct `allow`

Existing 0.7.2 cases must remain allowed, plus:

- `git fetch --all --prune`;
- optional `git fetch --prune --all` only if explicitly implemented;
- the exact trusted `ai-bridge host processes` wrapper invocation.

### Must remain effective `prompt` or otherwise outside direct allow

- bare/generic `ps`;
- `ps e`, `ps auxww`, or caller-selected cross-user process inspection;
- `kill`, `pkill`, `killall`, `renice`;
- `sudo ...`;
- arbitrary `bash -lc ...`, `sh -c ...`, Python or script wrappers;
- generic `git fetch <arbitrary-url>`;
- generic `git fetch origin <arbitrary-refspec>` forms not already explicitly authorized;
- destructive Git operations already gated by 0.7.2;
- all Slurm allocation/mutation cases already gated by 0.7.2.

## Regression requirements

Preserve all 0.7.2 Host Policy contracts:

- Slurm read-only direct allow and mutation gating;
- `ai-bridge plugin-replay` executable pinning and bounded replay;
- existing safe `origin/main` Git synchronization;
- ordinary task-owned staging/commit/push behavior;
- dangerous Git operations remaining gated;
- managed-block preservation and host-install backup/idempotency;
- narrative-language and external-review waiting policy.

Do not redesign unrelated Git rules unless a concrete 0.7.3 test demonstrates a conflict.

## Production smoke-test requirement

Before declaring `0.7.3` complete, deploy the candidate Host Policy to an affected remote Codex identity and verify through the normal production entry point that:

1. formatted `squeue` remains approval-free after 0.7.2 deployment;
2. the bounded current-user host process inventory runs without auto-review interruption;
3. `git fetch --all --prune` no longer triggers the reproduced false denial if that exact rule is implemented;
4. representative mutating process/Git/Slurm commands remain gated.

Do not mutate or cancel live Slurm jobs merely to prove negative cases; use execpolicy checks for destructive forms.

## Version and release boundary

If all acceptance criteria pass:

- bump `0.7.2 -> 0.7.3`;
- update version constants, README and CHANGELOG;
- extend `ai-bridge host validate` and real-Codex regression tests;
- keep this document as design rationale.

Do not call the release complete merely because a new wrapper exists or because synthetic tests pass. The user-visible success condition is that an unattended task can perform the reproduced low-risk host diagnostics through the supported production routes without being terminated by avoidable approval review, while nearby mutation surfaces remain gated.
