## 3. RL-B1 — unsandboxed execution fence

### 3.1 Why the fence is required

The selected Machine Policy rule will be:

```text
ai-bridge reviewed-handoff task bootstrap
-> allow
```

Current Codex behavior means this direct allow can bypass the outer workspace sandbox.

Therefore Bridge must ensure that the bounded helper itself cannot accidentally use Git or filesystem behavior to execute arbitrary repository-controlled programs or write through repository symlinks outside the intended sibling worktree.

The fence is deliberately **not** a generic Git security scanner. It covers only executable/write escape mechanisms reachable from the concrete bootstrap command sequence.

### 3.2 Concrete bootstrap Git sequence to protect

The retained bootstrap implementation conceptually does:

1. read/validate current repo/config/ref/worktree state;
2. create local branch `reviewed/<task_key>`;
3. run `git worktree add <derived-sibling> <derived-branch>`;
4. write task-owned `automation/reviewed_handoff/tasks/<task_key>/...` and `results/<task_key>/...`;
5. on partial failure, inspect current-invocation state and perform bounded rollback.

Relevant Git facts independently rechecked from official Git documentation:

- `reference-transaction` is invoked by Git commands that update refs;
- `git worktree add` performs checkout and runs `post-checkout`;
- `post-index-change` is invoked when Git writes the index;
- checkout may run configured `filter.<driver>.smudge` / `filter.<driver>.process` commands;
- an external-path `core.fsmonitor` can be invoked by Git operations that refresh/inspect the index, including the retained rollback cleanliness path if it uses `git status`.

### 3.3 Required pre-mutation executable fence

Before the **first topology mutation**, the helper must inspect the effective Git configuration/hook locations for the current repo and fail closed if any external executable path reachable by its retained command sequence is active.

At minimum reject:

#### Ref-update hook

```text
reference-transaction
```

Reason:
local branch creation updates refs.

The check must respect effective `core.hooksPath`, not only `.git/hooks`.

#### Checkout hook

```text
post-checkout
```

Reason:
`git worktree add` invokes it after checkout.

Again, inspect effective hooks path.

#### Index-write hook

```text
post-index-change
```

Reason:
the worktree/index creation path may write the new worktree index.

#### Checkout content filters

Reject configured external:

```text
filter.*.smudge
filter.*.process
```

that could run during checkout.

The Plan does not require banning harmless built-in text/eol/ident behavior; the concern is an external executable command.

#### External fsmonitor

If the retained implementation or rollback path can invoke an index-refresh/status operation, reject external command-valued:

```text
core.fsmonitor = <path/command>
```

Boolean built-in fsmonitor is not treated as an external executable solely because `core.fsmonitor=true`.

### 3.4 Simpler equivalent is allowed

Executor may remove a reachable executable path instead of fencing it if that is mechanically simpler and does not change product semantics.

Example:

- if the only reason bootstrap can invoke external `core.fsmonitor` is rollback's `git status --porcelain`,
- and rollback cleanliness can be proven safely without invoking that status path,
- then removing that invocation is acceptable and an fsmonitor rejection may become unnecessary for bootstrap.

The implementation must document which exact command sequence remains and demonstrate that every retained external executable path is either removed or rejected before mutation.

Do not broaden into unrelated Git hooks that the helper cannot invoke.

### 3.5 Preflight itself must be side-effect bounded

The executable-fence inspection must use direct filesystem/config reads that do not themselves execute the hook/filter/fsmonitor mechanism being inspected.

Do not use a diagnostic Git command that triggers the very executable path the preflight is supposed to reject.

## 4. Task/result write escape fence

After `git worktree add` succeeds but **before Bridge writes REQUEST/CURRENT/results**, verify that task-owned output paths remain inside the exact new worktree.

The vulnerable pattern to prevent is a tracked repository symlink such as:

```text
automation -> /outside
results -> /outside
```

or an intermediate component redirect.

### 4.1 Required paths

Protect every intermediate component used by:

```text
automation/
automation/reviewed_handoff/
automation/reviewed_handoff/tasks/
automation/reviewed_handoff/tasks/<task_key>/

results/
results/<task_key>/
```

and any template/input path whose write target is created beneath those trees.

### 4.2 Required mechanical rule

Before creating task/result directories or files:

1. start from the already-validated real sibling worktree root;
2. inspect each existing intermediate component with non-following filesystem semantics;
3. reject any existing symlink;
4. reject non-directory intermediate components;
5. for missing components, create them only beneath the previously verified non-symlink parent;
6. after creation, re-check that the actual directory chain remains under the exact sibling root before writing REQUEST/CURRENT.

A result equivalent to:

```text
BOOTSTRAP_OUTPUT_PATH_REDIRECTED
```

must occur before writing task/result content if the chain is unsafe.

The helper must not “resolve the symlink and see whether it looks okay”; the trusted bootstrap path simply does not follow repository-controlled symlinks for these output directories.

### 4.3 Rollback

If an unsafe output chain is detected after worktree checkout:

- do not write REQUEST/CURRENT/results;
- use only the already-approved current-invocation local rollback;
- do not unlink repository-owned symlinks as a “repair”;
- preserve ambiguous/dirty state.

## 5. RL-B2 — remote branch freshness

### 5.1 Problem

A network-free bootstrap that checks only:

```text
refs/remotes/origin/reviewed/<task_key>
```

is safe only if local remote-tracking state has just been synchronized.

Fetching only `origin/main` does not prove a remote task branch is absent.

Therefore a stale local ref view could incorrectly conclude:

```text
REMOTE_TASK_BRANCH_ABSENT
```

when `origin/reviewed/<task_key>` actually exists remotely.

### 5.2 Selected pre-bootstrap sync

Keep the permanently allowed bootstrap helper network-free.

Immediately before the bootstrap attempt, the repo-local Codex must run the already-existing Machine Policy low-friction sync:

```text
git fetch --all --prune
```

This is already an installed Bridge Machine Policy allow and does not require a new wrapper or approval path.

For the ordinary single-origin repos in scope, it refreshes/prunes the configured remote-tracking namespace, including the exact reviewed task branch.

Then bootstrap performs only local checks.

### 5.3 Bootstrap remote-branch check

After the sync, before branch creation, require:

```text
refs/remotes/origin/reviewed/<task_key>
```

to be absent locally.

If it exists:

```text
REMOTE_TASK_BRANCH_ALREADY_EXISTS
```

and no local branch/worktree/control-state mutation occurs.

The bootstrap helper must not run:

- `ls-remote`;
- `git fetch`;
- provider API;
- any other network command.

### 5.4 Base freshness uses the same sync

The same `git fetch --all --prune` establishes the current local:

```text
refs/remotes/origin/main
```

used by the v0.2 base rule.

The Kickoff/executor records the exact post-sync OID and passes:

```text
--expected-base-commit <post-sync origin/main OID>
```

Bootstrap requires exact equality with local `origin/main`.

This avoids two separate synchronization mechanisms.

### 5.5 Scope note

This recovery does not redesign the existing general `git fetch --all --prune` Machine Policy rule. It reuses an already-approved configured-remote synchronization capability.

The new bootstrap allow itself remains network-free.

## 8. Updated negative regression bank

Keep v0.2 negatives and add the two blocker-specific banks.

### RL-B1 executable/write escape negatives

- executable `reference-transaction` hook -> reject before branch mutation;
- executable `post-checkout` hook -> reject before mutation;
- executable `post-index-change` hook -> reject before mutation;
- effective `core.hooksPath` hook variants -> reject;
- external `filter.*.smudge` -> reject;
- external `filter.*.process` -> reject;
- external command-valued `core.fsmonitor` when reachable -> reject or prove command path removed;
- tracked `automation` symlink -> no task write;
- tracked `results` symlink -> no result write;
- symlinked intermediate under `automation/reviewed_handoff/tasks` -> no task write;
- non-directory intermediate component -> fail closed;
- no cleanup path follows/removes repository-controlled symlinks outside the sibling.

### RL-B2 remote freshness negatives

After a preflight sync fixture:

- remote `reviewed/<task_key>` exists -> local remote-tracking ref exists -> bootstrap rejects;
- remote branch deleted -> `--prune` removes stale remote-tracking ref -> bootstrap may proceed if all other conditions pass;
- stale/wrong expected base OID after sync -> reject;
- helper network-call canary -> zero network calls from bootstrap itself.

## 9. Red Team

Explicitly attack:

1. branch creation fires reference-transaction outside sandbox;
2. worktree checkout fires post-checkout outside sandbox;
3. index write fires post-index-change outside sandbox;
4. rollback `git status` runs external fsmonitor;
5. core.hooksPath moves hooks outside `.git/hooks`;
6. tracked `automation` or `results` symlink redirects Bridge writes;
7. nested intermediate symlink redirects task/result writes;
8. preflight inspects hooks using a Git command that itself executes them;
9. local remote-tracking branch is stale because only main was fetched;
10. bootstrap sneaks in `ls-remote` or a fetch after becoming allowlisted;
11. `fetch --all --prune` is skipped but absence is still claimed;
12. real AI_Skills sibling is replaced by a `/tmp` positive;
13. raw Git becomes allowlisted to work around the fence;
14. workflow-core starts before FB-G1-AT passes.
