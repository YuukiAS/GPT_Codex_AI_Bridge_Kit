## Goal

把当前 0.11.0 implementation branch 收敛成一个真正可用、低复杂度、可由同一 final candidate 直接验收的 Bridge Kit 0.11.0。

不要继续旧 Final Scope Recovery，也不要只修八个 finding 的表面症状。最终候选必须同时具备六项已经冻结的用户能力：

1. Host 的低打扰安全操作边界。
2. Lite/Review/Control/适用 Persistent 在 spawn 前绑定 exact execution context 和 mandatory source。
3. Lite/Persistent/Overleaf 对根 AGENTS.md 的安全、序列化写入。
4. Persistent Run 的断线存活、真实 progress、主动 ETA、非致命 progress fault 和有出口的异常恢复。
5. 每个 OS 用户一份机器级 Notifier，所有 repo 共用，Lite/Review/Control/Persistent 四个真实 consumer 直接调用。
6. 自动邮件最多一次 Clear Writing，失败 fallback，整个 deliver 有硬墙钟 deadline，不能拖死业务。

## 必须实现的具体行为

### Machine Notifier

唯一 secret authority 是：

~/.ai-bridge/private/notifier.env

所有新 repo 不需要再复制 Gmail/App Password。repo-local .ai-bridge/private/notifier.env 只能作为显式 legacy migration input，runtime 永远忽略。

生产 normal entry 的 SMTP user、SMTP password、FROM、默认 TO、subject prefix 和其他 transport 配置只能来自 ~/.ai-bridge/private/notifier.env。AI_BRIDGE_NOTIFY_SMTP_USER、AI_BRIDGE_NOTIFY_SMTP_PASSWORD、AI_BRIDGE_NOTIFY_FROM、AI_BRIDGE_NOTIFY_TO、AI_BRIDGE_NOTIFY_SUBJECT_PREFIX 以及其他 AI_BRIDGE_NOTIFY_* 环境变量不得覆盖、合并或改变 production effective config。

逐任务唯一允许的收件人变化是冻结任务合同的 recipient_override；它不是 SMTP credential/config override。AI_BRIDGE_PRIVATE_RCLONE_SOURCE 等 private sync 导入变量不属于 runtime transport config。测试只能通过显式函数参数、dependency injection 或 temporary config/state root 注入测试配置，不能把 production 环境变量 override 留作第二套 authority。

保留 Gmail SMTP 587 + STARTTLS + App Password。notify 默认 OFF。

必须提供并真正工作：

- ai-bridge private sync --profile notifier
- ai-bridge notifier validate
- ai-bridge notifier send-test
- ai-bridge notifier status
- ai-bridge notifier migrate-legacy --project ...
- ai-bridge notifier retry --event-key ...

migrate-legacy 不删除旧文件；machine config 不存在时安全复制，相同 digest 时 no-op，不同 digest 时 conflict/no overwrite。

send-test 的成功语义只允许写 SMTP accepted，不得写 inbox delivered。readiness 绑定 redacted config digest；machine config 变化后 readiness 失效。

Notifier state 使用 machine-local per-event atomic claim/attempt/receipt。event identity 必须隔离不同 repo、相同 task key 和不同 runtime/semantic event。

FAILED 只允许显式 retry；DELIVERY_UNKNOWN 的 retry 必须要求确认可能重复。retry 使用冻结 request/recipient/lineage，不重新读后来变化的 repo brief。

### Auto NotificationRequest

自动 consumer 只能传安全白名单字段。禁止默认传入 details、jobs、stdout/stderr、env、secret、raw source、review body、任意私有正文和任意 evidence_paths。

recipient_override 只进入 transport，不进入 Clear Writing。拒绝 header injection。

manual legacy notifier send 可以兼容，但不得被拿来证明四 consumer 已接线。

### Clear Writing

正式依赖必须与 AI_Skills_Collection 当前正式 writing-style 对齐：

writing-fidelity + response-clarity

必须使用 current writing-style v0.5 的 response-clarity；不修改 AI_Skills。chinese-prose 不再是 automatic status/progress notification 的正式依赖。

每个自动 logical delivery 最多一个 codex exec --ephemeral --json、一个 turn、模型 retry=0、read-only sandbox。Clear Writing 最多 90 秒。模型输入必须使用 reader-facing projection：保留人需要的状态/进度/ETA/版本等事实，不强制显示 consumer/fact_class/decision_authority/runtime_id/source_event_id/schema；runtime start/terminal 无有意义 ETA 时不强制显示 UNKNOWN。fidelity 仍从原始 request 判断 runtime_* 不得升级成 semantic completion。任何失败立即 deterministic fallback。

### End-to-end deliver deadline

自动 deliver 从 consumer 提交开始总墙钟最多 120 秒。必须放在一次性可终止 helper/subprocess 中，父进程用 monotonic absolute deadline 控制；到期 terminate/kill helper。

DNS、connect、TLS、login、send 都受剩余 deadline 限制。

transport 尚未开始的超时是 definitive failed；transport 已开始但结果不明是 DELIVERY_UNKNOWN；已记录 SMTP_ACCEPTED 可恢复 accepted receipt。

任何通知失败、超时或未知都不能杀 primary child、改变业务 state 或回滚 Review/Control transition。

### Four consumers

Lite：现有 Lite task frontmatter 增加 notify=false、recipient_override。run_lite_task 只能发送 runtime terminal facts。exit code 0 不能写 semantic PASS。若运行在 Persistent child 内，检测 AI_BRIDGE_RUNTIME_OWNER=persistent，Lite runtime terminal suppress。

Review：notification policy 放现有 REQUEST.md。Reviewer 决定仍由 record_review/REVIEW_n/CURRENT 产生；现有 reviewed_runner watcher 在 validate_task 验证 Reviewer 事实后调用 Notifier。watcher 不产生 Reviewer authority；不得因 watcher 长时间运行给它再套 Persistent。

Control：notification policy 放现有 REQUEST.json。现有 apply_transition 在 predicate/角色 artifact/state/post-validation 全部成功后调用 Notifier；语义来自原角色 artifact。Notifier 失败不能回滚 transition。不得因 Controller 长时间运行给它再套 Persistent。

Persistent：supervisor 只发送 start/progress/stall/runtime terminal，不发送 semantic PASS/READY/RELEASE_READY。

### Persistent progress and ETA

Goal contract 必须冻结 progress_mode、progress_owner、source、expected update cadence、Notify、Recipient override、notification cadence。

count/fraction 必须有真实 producer。bridge-child 使用正式 progress update；project-native 使用项目已有 producer。stage/none 可保持 ETA UNKNOWN。

supervisor 给 child 注入 AI_BRIDGE_RUN_KEY、AI_BRIDGE_PROGRESS_PATH、AI_BRIDGE_PROGRESS_MODE、AI_BRIDGE_PROGRESS_OWNER、AI_BRIDGE_PROGRESS_EXPECTED_UPDATE_SECONDS、AI_BRIDGE_RUNTIME_OWNER、AI_BRIDGE_RUNTIME_ID。

progress update 原子写。

supervisor 每 60 秒 observation；一次 missing/half-written/bad JSON/OSError 只记录 observation unavailable，保留 last-good 并下一轮继续，绝不退出 supervisor、绝不杀 child。

count/fraction 的 ETA：至少 3 个有效点且跨至少 10 分钟后，用最近最多 60 分钟/12 点的有效近期推进率计算稳健中心 ETA 和可用区间。stage/total 改变、进度回退、长 gap 或速度失真时旧 ETA 失效并重新 warm-up。持续得到合法量化进度却始终没有 ETA 是 C4 failure。

### Persistent recovery

必须实现：

- persistent-run recover
- persistent-run resolve --close-stale

recover 识别 ACTIVE、ORPHAN_CHILD_ALIVE、SAFE_TO_CLOSE_STALE、DUPLICATE_RISK_UNRESOLVED、IDENTITY_CONFLICT，并给唯一安全下一动作。

process identity 只用于避免重复运行，不得证明 Goal completion。

只有 SAFE_TO_CLOSE_STALE + exact launch identity + session absent 才能 close stale。resolve 不删 binding、不写伪 exit code、不发 semantic completion；写 STALE_CLOSED_WITHOUT_COMPLETION。再次运行必须新 run identity。

用户不得被要求手工删 machine state。

### AGENTS.md transaction

Lite/Persistent/Overleaf 三个 writer 必须共用 target-level Bridge lock。

锁内完成 read → splice → instruction config/budget → temp+fsync → os.replace。Bridge writer 互相不能覆盖。overflow/config failure 零 AGENTS mutation，用户区域 byte-identical。

不要宣称对不合作外部 writer 有 portable CAS；只能 fail closed on detected external conflict。

### Existing exact execution/source preflight

保留 current narrow design：wrong repo/worktree/branch/HEAD/mandatory source 时 child=0；unrelated dirty 不阻断；commit blob authority；local exact object first；missing blob only then isolated fallback。不要恢复 general readiness controller 或 worktree exchange。

## Final-review repair
